## 0. 이 게임이 뭔가

**반응속도를 뺀 핵앤슬래시.**

- 시원하게 쓸어버리는 맛이 중심이다
- 그런데 손가락 속도는 안 쓴다. 생각할 시간은 무한하다
- 적 공격을 타이밍 맞춰 멋지게 흘리는 맛도 같이 가져간다

무쌍처럼 버튼만 누르는 게임도 아니고, 한 수 한 수 계산하는 전술 RPG도 아니다.
그 사이 좁은 자리를 노린다.

## 1. 설계 원칙 — 수싸움 금지선

가장 중요한 한 줄.

> **정밀함이 요구되면 수싸움. 정밀함이 보상이면 시원함.**

이 선을 넘는지로 모든 결정을 판단한다.

| 죽임 (수싸움) | 살림 (시원함) |
|---|---|
| 적이 하나 → 결투 | 적이 여럿 → 쓸어버림 |
| 정답이 하나뿐 | 정답이 없고 고르는 것 |
| 계산해야 알 수 있음 | 보면 알 수 있음 |
| 잘못 두면 **벌** | 잘 두면 **더 많이** |
| 되돌리기로 최적해 탐색 | 던지면 굳음. 넘어감 |
| 틱을 딱 맞추는 퍼즐 | 틱이 넘쳐 흐름 |
| 정밀함이 생존 조건 | 정밀함이 욕심 |

> 판단: **되돌리기가 수싸움을 만든다.** 사람은 되돌릴 수 있으면 반드시 계산한다.
> 즉시 해소 + 되돌리기 없음이 구조적으로 계산을 막아 준다.

## 1-2. 결정론 — 예측 상자를 떠받치는 기둥

> **무작위를 넣지 않는다. 미래는 언제나 100% 예측 가능해야 한다.**

### 왜 지켜야 하나

예측 상자가 이 게임의 하중을 받는다.
대상 지정(카드 5장 × 대상 여럿)도, 마릿수도, 모양도, 전부
**"답을 즉시 보여 주는 장치가 있으니 계산이 아니라 감각"** 이라는 전제 위에 서 있다.

무작위를 넣는 순간 예측 상자가 `받을 피해 4~8` 이 된다.
그러면 그 상자는 판단 근거가 못 되고, 늘어난 선택지가 곧장 수싸움으로 굴러떨어진다.

**무작위는 수싸움도 시원함도 아니다. 그냥 운이다.**

### 어떻게 100%가 되나

예측이 별도의 추정 공식을 쓰지 않는다. **엔진 그 자체를 돌린다.**

```
throwCard  →  startAct + stepTick × N
dryRun     →  startAct + stepTick × N + 되돌리기      ← 같은 함수
```

- [x] `stepTick` 에 무작위가 없다
- [x] 몹 AI 는 `사거리 안이면 공격, 밖이면 이동` 분기 하나뿐이다
- [x] `dryRun` 이 세계를 통째로 저장했다 돌려 놓는다
- [x] **무작위 판 400회에서 예측과 실제가 한 톨도 안 틀렸다**
      (줄 피해 · 처치 · 받을 피해 · 적 공격 횟수 · 누가 맞는지 전부)

### 그래서 공짜로 얻는 것

- [ ] **스턴 · 공중띄움 같이 예고를 끊는 기능**을 넣어도 예측이 저절로 맞는다.
      `stepTick` 안에서 예고를 끊으면 `dryRun` 도 똑같이 끊는다.
      예측 코드를 따로 짤 필요가 없다

### 예측이 깨지는 자리 — 넷 중 둘

| 시나리오 | 깨지나 | 대처 |
|---|---|---|
| **무작위** (명중 굴림 · 무작위 패턴 · 무작위 리젠) | **깨진다** | **넣지 않는다** |
| **인스턴트 카드** (3-3) | **깨진다** | 예측을 `안 끼어들면` 기준으로 명시 |
| 몹이 내 계획에 반응 | 안 깨진다 | 여전히 결정론이다 |
| 보여 줄 게 너무 많음 | 안 깨진다 | 표현의 문제다. 아래 참고 |

> 인스턴트만은 어쩔 수 없다. 6틱 기술 도중 3틱째에 내가 끼어들지는
> **지금 결정되지 않았다.** 미래가 내 미래 입력에 달린다.
> 다만 끼어드는 순간 화면이 멈추고 다시 묻게 되므로,
> 그 시점에 새 예측을 주면 된다. 예측을 `안 끼어들면` 기준으로 적는 것으로 충분하다.

### 겪은 일 — 예측이 아니라 표시가 문제였다

플레이 중 손패 카드에 `사거리 밖` 딱지가 떴는데 실제로는 맞았다.
엔진은 맞았고, **딱지가 반쪽 정보**였다.

- 손패 딱지는 `가장 가까운 적을 겨눈다면` 을 가정하고 있었다.
  다른 놈을 겨누면 결과가 달라지는데 그 말을 안 했다
- [x] 고침: **어느 대상에게 써도 소용없을 때만** 딱지를 붙인다

같이 잡은 것:

- [x] 예측 캐시 열쇠가 `카드·대상·던진 횟수` 였다. 그 사이 판이 바뀌면 캐시가 거짓말했다.
      열쇠에 **판 상태를 통째로** 넣어 구조적으로 없앴다.
      언제 무효로 할지 손으로 챙기지 않아도 된다

## 2. 구조 전환 — 일괄에서 즉시로

| | 옛 구조 (지금 코드) | 새 구조 |
|---|---|---|
| 결정 단위 | 10틱을 한 번에 배치 | **카드 한 장씩** |
| 시간 | 확정 후 10틱 재생 | **던진 카드의 틱만큼 흐름** |
| 피드백 | 결정 4번에 피드백 1번 | **결정 1번에 피드백 1번** |
| 몹 예고 | 10틱 타임라인 전부 | **머리 위 숫자 하나** |
| 되돌리기 | 있음 | **없음** |
| 계산 부담 | 10틱을 머리로 시뮬 | 없음. 숫자 읽고 던짐 |

> 판단: 시원함은 **연출이 안 끊기는 것**이 아니라 **입력과 결과 사이가 짧은 것**이다.
> 핵앤슬래시는 10초짜리 컷신이 아니라 클릭-타격-클릭-타격이다.
>
> 판단: 계획 단계가 수싸움의 서식지였다. 드라이런·소용없음 미리보기·틱 예산 퍼즐이
> 전부 일괄 때문에 생겼다. 즉시로 가면 통째로 사라진다.
>
> 판단: 적이 여덟이면 10틱을 미리 짜는 건 조합 폭발이다.
> **일괄은 적이 하나일 때만 편하고, 적이 하나면 결투라 수싸움이다.**
> 즉 일괄은 수싸움을 강제하는 구조였다.

### 한 줄 규칙

> **틱은 내가 카드를 던질 때만 흐른다.**

반응속도가 원천적으로 필요 없어진다. 화면은 액션인데 시간은 내 것이다.
(같은 발상: 슈퍼핫, 그리고 로그라이크의 턴제 시간)

## 3. 핵심 루프

- [x] 몹마다 머리 위에 **다음 행동까지 남은 틱** 숫자를 띄운다
- [x] 손패에서 카드 한 장을 던진다
- [x] 그 카드의 틱 수만큼 시간이 흐른다. 몹 숫자도 그만큼 줄어든다
- [x] 0이 된 몹은 그 자리에서 행동하고, 새 숫자를 받는다
- [ ] 즉시 연출이 터진다  ← 아직. 다음 덩어리
- [x] 손패를 보충한다. 다시 던진다

```
몹A[1]  몹B[3]  몹C[1]
손패: 공격3 · 회피1 · 선회1 · 대기1 · 선풍4

회피 던짐 → A·C 둘 다 그 틱에 침 → 둘 다 간발로 흘림 → 틱 2 환급 · 화면 정지
            그 사이 B는 [2]
환급 틱으로 선풍 → 셋 다 후려침
```

읽는 데 1초. 계산 없음.

### 라운드는 없다 (확정)

한 판은 10틱이 아니다. 시간은 끊기지 않고 흐른다.
판이 끝나는 것은 **목표를 달성했을 때**다.

| 모드 | 끝나는 조건 | 순서 |
|---|---|---|
| **섬멸** | 맵의 몹을 다 죽임 | 첫 구현 |
| 타임어택 | 정해진 틱을 버팀 (리젠 몹) | 나중 |
| 보스 | 보스를 죽임 | 나중 |

> 판단: 타임어택도 **분이 아니라 틱**으로 잰다.
> 실시간 분으로 재면 빨리 던지는 게 유리해져서 **반응속도가 다시 들어온다.**

### 전장 (v1.6.0)

전장을 탭으로 고른다. 코드가 아니라 **표 한 줄**로 판을 짠다.

```js
{ id, name, hint, spots:[[종류, 각(회전수), 거리(걸음)], ...] }
```

| 전장 | 배치 | 가르치는 것 |
|---|---|---|
| **졸개 셋** | 졸개 3 (9~11걸음) | 예고를 읽고 흘린다 |
| **무식한 놈** | 무식한 놈 1 (13걸음) + 졸개 4 (8·11·15·18걸음) | 빔을 선회로 피하고 유도한다 |

- [x] 탭을 누르면 그 전장으로 새로 시작한다
- [x] 몹 종류를 `KINDS` 로 나눴다. `atkAct` 만 갈아 끼우면 성격이 바뀐다
- [x] 잡몹 거리를 벌려 **파도처럼** 들어오게 했다. 한꺼번에 붙으면 손쓸 새가 없다

### 난이도 — 봇 다섯으로 재 봤다

예측 상자만 보고 두는 봇에 성향을 다르게 줘서 돌렸다.

| 성향 | 전장 0 | 전장 1 |
|---|---|---|
| 겁쟁이 (위험 회피 강함) | 9수 · 체력 18 · 승 | 48수 · 체력 8 · **승** |
| 보통 | 12수 · 체력 10 · 승 | 41수 · 체력 6 · **승** |
| 공격적 | 7수 · 체력 18 · 승 | 38수 · 체력 0 · 패 |
| 유도꾼 (아군 오사 중시) | 7수 · 체력 16 · 승 | 63수 · 체력 2 · **승** |
| 막가파 (위험 무시) | 7수 · 체력 8 · 승 | 33수 · 체력 0 · 패 |
| | **5/5 승** | **3/5 승** |

> 읽히는 것: **전장 0 은 몸풀기**, **전장 1 은 신중하면 이기고 막가면 진다.**
> 겁쟁이가 가장 많은 체력을 남기고 막가파가 죽는다 — 의도한 교훈 그대로다.
>
> 주의: 봇은 카오스적이다. 값 하나만 바꿔도 궤적이 완전히 달라진다.
> **한 판만 보고 조정하면 안 된다.** 성향을 여럿 돌려 분포로 봐야 한다.

### 틱이 예산에서 비용으로

상한이 사라지므로 틱을 누르는 압력은 **"그동안 적이 움직인다"** 하나뿐이다.
적이 하나면 4틱 카드나 1틱 카드나 차이가 없어 **틱 시스템이 무의미해진다.**

그래서 **잡몹 여럿이 선택이 아니라 전제 조건**이 된다.

### 드로우 (확정)

- [x] 손패 **5장**. 한 장 던지면 한 장 즉시 보충
- [x] 덱이 비면 무덤을 섞어 되쓴다
- [x] 덱 크기는 사실상 **확률 분포** 역할만 한다 (무한 순환이므로)

## 3-2. 공격 발동은 **마지막 틱** (확정)

옛 규칙은 "효과는 점유 첫 틱에 발동" 이었다.
일괄 구조에서는 몹의 10틱 타임라인이 미리 다 공개돼서 그래도 예고가 됐다.

**즉시 해소로 가면 그게 무너진다.** 몹이 제 차례에 행동을 고르는데
첫 틱에 발동하면 예고가 뜨는 순간 이미 맞은 것이다. 피할 창이 0틱이다.

```
옛:  [발동][경직][경직]   ← 예고 뜨자마자 맞음
새:  [시전][시전][발동]   ← 2틱 동안 피할 수 있음
```

- [x] 공격 · 선풍의 발동을 **마지막 틱**으로 옮긴다
- [x] 이동 계열은 그대로 점유 틱에 걸쳐 활주한다
- [x] 조준은 **발동 틱에** 한다 (`조준` 스탯이 있는 액터만)

> 판단: 카드는 여전히 **숫자 하나(틱 수)** 만 갖는다. 발동 위치만 앞에서 뒤로 옮겼다.
> 복잡도는 안 늘어난다.
>
> 판단: 이래야 **머리 위 숫자의 뜻이 명확해진다** — "몇 틱 뒤에 맞는다".
> 첫 틱 발동이면 숫자가 "행동이 끝날 때까지" 라 뜻이 흐리다.

## 3-3. 인스턴트 카드 (아이디어 · 기록만)

> 아직 구현하지 않는다. 방향만 적어 둔다.

시간이 흐르는 **도중에** 끼어들어 쓰는 카드.

```
내가 6틱짜리 큰 공격을 던짐
  → 3틱째에 적 공격이 발동함
  → 그 자리에서 멈추고 "인스턴트 쓸래?" 를 묻는다
  → 회피 · 막기 같은 인스턴트를 냄
```

### 왜 이게 값을 하나

- **긴 카드를 설계할 수 있게 된다.** 인스턴트가 없으면 6틱 대형기는 그냥 자살이다.
  받아낼 수단이 있어야 큰 카드가 성립한다
- **반응속도를 안 쓴다.** 적 공격 발동 틱에 화면이 **자동으로 멈춰서** 묻는다.
  생각할 시간은 무한하다. 즉시 해소 구조라서 가능한 것이다
- **간발과 한 몸이다.** 인스턴트 회피는 정확히 그 틱에 쓰는 것이므로 자동으로 간발이다

### 정해야 할 것

- 자원 제한 — 무한히 쓰면 다 막는다. 후보: 판당 횟수 / 별도 자원 /
  인스턴트 전용 손패 칸 / 틱 비용 후불(진행 중 카드의 남은 틱에 +1)
- 인스턴트로 쓸 수 있는 카드를 따로 표시할지, 아무 카드나 되는지
- UI — 멈춘 순간 인스턴트 가능한 카드만 밝게

---

### 틱 비용이 추상에서 체감으로

일괄에서 `선풍 4틱` 은 예산표의 칸 하나였다.
즉시에서는 **던지는 순간 적들이 4틱어치 다가온다.** 눈으로 본다.

카드 틱 수가 오히려 더 살아난다.

- [x] 공격 예고 중인 몹은 무대에 **위험 지대**(부채꼴)를 깐다

> 판단: 예고를 10틱 전부 공개하면 모든 게 계산 가능해져서 즉시 해소가
> **느려진 일괄**이 된다. 숫자 하나로 줄여야 즉시 해소가 값을 한다.
>
> 판단: 예고를 "정밀 타이밍"이 아니라 **"공간 위험 지대"** 로 읽히게 한다.
> 디아블로의 붉은 장판이다. 계산이 아니라 눈으로 보고 비키는 것.

## 5. 간발 — 타이밍 회피를 수싸움 없이

### 지금 무엇이 문제인가

현재 회피는 물러난 거리가 판 끝까지 남는다. 그래서 **일찍 피해도 똑같이 안 맞는다.**

```
[대기, 회피]              → 체력 20  (공격보다 이름)
[대기, 대기, 회피]        → 체력 20  (같은 틱)
[대기, 대기, 대기, 회피]  → 체력 18  (늦음)
```

늦은 것만 벌 받는다. **타이밍 재미가 구조적으로 없다.**
지금 있는 건 "미리 도망가기"지 "멋지게 피하기"가 아니다.

### 고칠 것 — 그 틱에만 열리는 창

- [ ] 회피 1틱 = 그 틱 동안 **회피 상태**
- [ ] 그 틱에 발동한 공격은 **거리·각도 무관 무조건 빗나감**
- [ ] 물러나는 것은 그대로 유지한다
- [ ] 선회도 같은 창을 갖는다

### 층을 둘로 — 난이도가 강제가 아니라 선택

| 방식 | 안전도 | 보상 |
|---|---|---|
| **미리 물러남** (거리로) | 안전. 누구나 | 없음. 다시 붙어야 한다 |
| **간발 회피** (그 틱에) | 아슬. 붙어 있다 | 틱 환급 · 반격 창 · 연출 |
| **간발 선회** (그 틱에) | 아슬 | 위 + 측면·후방 확보 |

> 판단: **안전 경로가 항상 열려 있어야 한다.**
> 초보는 도망가면 되고, 잘하면 붙어서 아슬하게 흘리고 반격한다.
> 정밀함이 생존 조건이 아니라 욕심이 되므로 수싸움이 아니다.

### 보상은 시원함으로 되돌린다

- [ ] 간발 성공 시 **틱 1~2 환급**
- [ ] **반격 창** — 다음 공격 카드 1틱 감소
- [ ] 순간 정지 · 섬광 · 잔상

여럿을 한 번에 흘리면 환급이 쌓인다.
**피하는 것이 딜을 깎지 않고 딜로 되돌아온다.** 무쌍과 갈리는 지점이다.

### 외워서 자동화되지 않으려면

몹이 하나면 "머리에 1 뜨면 회피"로 자동화된다. 지루하다.
**여덟이면 불가능하다.**

```
몹A[1]  몹B[3]  몹C[1]  몹D[1]  몹E[5]
```

A·C·D를 한 번에 흘릴까, B를 기다려 더 큰 판을 만들까 — **계산이 아니라 선택**이다.

자동화를 막는 마찰 셋:

| 마찰 | 내용 |
|---|---|
| **여럿** | 누구 걸 받아낼지 골라야 한다 ← 제일 크다 |
| **모양** | 직선은 선회로만, 리치와 범위는 회피로만 (8-2) ← 두 번째 |
| **손패** | 1틱 카드가 손에 없을 수 있다. 버리기로 갈 수는 있지만 그것도 1틱이다 |
| **딜 손실** | 창을 맞추려 1틱짜리로 시간을 째면 공격을 못 한다 |

### 용어

- [ ] **간발** — "간발의 차"가 이미 쓰는 말이라 설명이 필요 없다
- 후보로 굴렸던 것: 찰나 · 아슬
- `간발 회피` · `간발 선회` · `간발 성공` 으로 붙여 쓴다

### 하지 말 것

- 간발을 **생존 필수**로 만들기 → 그 순간 수싸움으로 굴러떨어진다
- 실패에 큰 벌 → 한 대 맞고 마는 정도
- 창을 반 틱처럼 좁게 → 정밀함이 요구가 되어 버린다
- 몹 예고를 숫자 하나보다 복잡하게

## 6. 잡몹 여럿 — 가장 큰 레버

- [x] 첫 구현은 **졸개 3마리**. 나중에 5~8로
- [x] 안 죽는 허수아비가 아니라 **두 대에 죽는 잡몹**
- [ ] 허수아비는 지웠다. 필요하면 되살린다

### 졸개 (첫 몹 · 확정)

가장 기초가 되는 몹. **다가와서 친다.** 그게 전부다.

| 값 | 수치 | 근거 |
|---|---|---|
| 체력 | **6** | 플레이어 공격력 3 → 정확히 **두 대** |
| 공격력 | 2 | 플레이어 체력 20 → 열 대 |
| 사거리 | 1.6 | 플레이어 2.0보다 짧다. 붙어야 친다 |
| 조준각 | 30도 | 그대로 |
| 이동 | 1.2 / 2틱 = 틱당 0.6 | 플레이어 0.75보다 **느리다** → 도망 여지 |
| 공격 | 3틱 (마지막 틱 발동) | 2틱의 회피 창 |
| 조준 | **없음** | 예고한 방향으로만 친다 |

#### AI — 분기 하나

```
사거리 안  →  공격 (3틱)
사거리 밖  →  이동 (2틱)
```

행동이 끝나면 그 자리에서 다시 고른다. 몹마다 **독립 시계**를 갖는다.

#### 방향 처리 — 여기가 미묘하다

허수아비는 안 움직여서 방향이 굳었고, 그래서 선회가 통했다.
**다가오는 몹은 이동하며 계속 재조준한다.** 그대로 두면 선회가 약해진다.

- [x] 몹은 **이동할 때** 방향을 갱신한다
- [x] **공격 예고를 시작할 때 대상 쪽으로 조준한다**
- [x] 그 뒤 발동까지 방향은 **굳는다**. 중간에 다시 안 돈다

> 판단: 예고는 "이 방향으로 친다" 는 **약속**이다.
> 발동 때 다시 조준하면 예고가 거짓말이 된다. 나에게도 몹에게도 똑같이 적용한다.
>
> **고침 (v1.0.1)**: 처음에는 방향을 이동할 때만 갱신했다.
> 그랬더니 붙어서 공격만 반복하는 몹은 방향이 영영 안 바뀌어,
> **한 번 선회하면 그 뒤로 영영 못 맞히는 바보**가 됐다.
> 예고를 **시작하는 순간** 조준하도록 고쳤다.
>
> 이래도 선회는 그대로 통한다. 예고 3틱 중 아무 때나 45도 돌면 조준각 30도를 벗어난다.
> 다만 **매 예고마다 다시 흘려야 한다.** 한 번 돌고 손 놓으면 다음 예고에 맞는다.
> 일회성 해법에서 **계속 이어 가는 싸움**으로 바뀌었다.
>
> 선풍은 전방위라 조준을 안 쓰므로 방향을 건드리지 않는다.
>
> **대칭 맞춤 (v1.0.2)**: 플레이어만 발동 틱에 다시 조준하고 있었다.
> 그 줄을 떼어 나와 몹이 한 규칙을 쓴다.
> 이제 **내가 긴 공격을 준비하는 동안 몹이 빠지면 나도 빗나간다.**

- [x] 몹끼리 겹치는 것은 당장 막지 않는다 (셋이 모이면 뭉친다). 나중에 볼 것

### 배치

- [x] 플레이어 중심으로 흩어서 거리 4~6. 서로 다른 방향에서 온다

> 판단: **1대1은 무조건 결투이고, 결투는 수싸움이다.** 마릿수가 장르를 바꾼다.

증거가 이미 코드에 있다. 지금 `선풍` 은 `공격` 보다 모든 면에서 나쁘다.

| | 공격 | 선풍 |
|---|---|---|
| 틱 | 3 | 4 |
| 사거리 | 2.0 | 1.6 |
| 맞는 수 | 1 | 1 ← 적이 하나라서 |

적이 다섯이면 선풍이 최고 카드가 된다.
**카드는 안 고쳐도 된다. 마릿수만 바꾸면 카드 설계가 살아난다.**

여럿이 세 군데에서 동시에 값을 한다.

1. 카드 설계를 살린다 (광역이 의미를 갖는다)
2. 간발의 자동화를 막는다 (누구 걸 받아낼지 고른다)
3. 즉시 해소를 정당화한다 (여럿을 미리 짜는 건 지옥이다)

- [ ] 마릿수를 늘리기 전에 **모양이 다른 몹**을 먼저 넣는다 (8-2)
      같은 졸개 여덟보다 졸개·창잡이·사수 셋이 훨씬 다르다

- 예측 상자가 그 값을 즉시 보여 준다

      그때 **판당 N회 상한**을 걸면 된다. 지금은 불필요

> "누구 걸 받아낼지 고르는 선택" 인데 **칠 대상은 못 골랐다.**
>
> **3. 결정적 — 선회의 축을 골라야 한다.** 8-2 의 모양 축과 맞물린다.
> 사수의 빔을 피하려면 **사수를 축으로** 돌아야 하는데,
> 가장 가까운 놈이 축이면 못 고른다.
> **빔을 넣는 순간 대상 지정이 없으면 선회가 반쯤 망가진다.**

### 덤 — 공격에 각 맞추기가 생긴다

`fire()` 는 **조준각 안 모든 적**을 친다. 그런데 조준은 대상 쪽으로 한 번만 한다.
대상을 고를 수 있으면 **둘이 겹치는 각을 노릴 수 있다.**

```
몹 A 와 B 가 얼추 한 줄로 서 있으면
→ 뒤쪽 B 를 대상으로 잡아 A 까지 함께 벤다
```

계산이 아니다. 예측 상자가 `줄 피해 6` 이라고 바로 말해 준다.

### 위험과 완화

| 위험 | 완화 |
|---|---|
| **선택지 폭발** — 카드 5장 × 대상 3 = 15가지 | **예측 상자.** 손이 몹 위를 지나가면 숫자가 실시간으로 바뀐다. 훑어서 계산하는 게 아니라 움직이며 보는 것이 된다 |
| 손 정밀도 요구 | 드롭 지점에서 가장 가까운 몹으로 **붙인다.** 빗나가는 드롭이 없다 |
| 대상 없는 카드가 섞임 | 고리로 구분한다 |

> 판단: **예측 상자가 없었으면 이 변경은 안 했을 것이다.**
> 대상이 늘면 선택지가 곱해지는데, 답을 바로 보여 주는 장치가 있어야
> 수싸움으로 안 미끄러진다.

### 안 하는 것

- [ ] **위치 지정은 안 한다.** "이동을 빈 땅으로" 는 매력적이지만
      대상 지정과 섞이면 복잡해진다. 이동도 `대상을 향해 3걸음` 그대로 둔다

### 몹은 그대로

몹 AI 는 계속 가장 가까운 적(=플레이어)을 쓴다. 하나뿐이라 문제가 없다.
**나만 고를 수 있는 비대칭**인데, `조준` 스탯처럼 정당화된다 — 의지가 있는 쪽이 고른다.

### 대상이 도중에 죽으면

- [x] 행동이 붙잡은 대상이 죽으면 **가장 가까운 적으로 물러선다.** 카드가 헛돌지 않는다

### 검증한 것

```
좌표 왕복        화면 좌표 → 걸음 좌표 → 화면 좌표, 오차 없음
대상 고르기      오른쪽/아래/왼쪽 몹 위에 떨구면 각각 그놈이 대상
빈 땅            9걸음 허공에 떨궈도 그쪽 몹으로 붙음
이동             가까운 놈(5걸음)이 아니라 고른 놈(5걸음, 다른 방향)에게 3걸음
회피             고른 몹의 반대로 4걸음
선회             고른 축과의 거리는 유지, 다른 몹과의 거리는 바뀜
공격             고른 몹만 맞음 (6/3)
겹치는 각        한 줄로 선 둘 중 뒤쪽을 겨눠 앞쪽까지 벰 (3/3)
예측             대상마다 다르다 — 줄 피해 3 vs 0, 먼 쪽은 사거리 밖
드래그           손을 옮기면 대상도 바뀐다
선풍             대상을 안 고른다
대상 사망        가까운 적으로 물러서서 그놈을 친다
```

> 시험 중 발견: 12걸음 밖의 몹을 겨누면 `사거리 밖` 이 되지만,
> **6걸음이면 3틱 동안 다가와서 맞는다.**
> 예측이 "지금 거리" 가 아니라 **"터질 때 거리"** 로 답하고 있다는 뜻이다. 옳다.

## 8. 공간과 판정 — 살아남는 규칙

옛 구조에서 만든 것 중 즉시 해소로 가도 **그대로 쓸 수 있는 것들**이다.

### 공간 — 걸음과 눈금 (v1.2.0)

시간의 단위가 **틱**이듯 거리의 단위는 **걸음**, 각도의 단위는 **눈금**이다.

- [x] **걸음** — 거리는 전부 걸음으로 잰다. 값은 모두 정수
- [x] **눈금** — 원을 12로 나눈 하나 = 30도. 조준각은 `정면 ±1눈금`
- [x] 연속 2D, 쿼터뷰 렌더 · 지형 무제한 · 벽 없음
- [x] 접촉거리 **1걸음** — 이보다 가까이 못 붙고, 뚫고 지나가지 않는다
- [x] 지면 한 칸이 1걸음. **4걸음(사거리)마다 굵게** 그어 눈으로 셀 수 있게 한다

> 짚어둘 것: **정수 단위가 격자는 아니다.**
> 틱이 정수라고 시간이 뚝뚝 끊기지 않듯, 걸음이 정수라도 위치는 계속 소수다.
> 정해지는 것은 *양*이지 *자리*가 아니다.

### 선회는 각도가 아니라 걸음이다 (v1.2.0)

예전에는 선회를 **45도 고정**으로 뒀다. 그랬더니 호 길이가 거리에 비례해 터졌다.

| 몹까지 | 옛 규칙(45° 고정)이 실제로 옮기는 거리 |
|---|---|
| 2걸음 | 1.6 |
| 4걸음 | 3.1 |
| **10걸음** | **7.9** ← 이동(3걸음)보다 2.6배, 틱은 절반 |

멀리서 선회하면 사실상 순간이동이었다.

- [x] 선회 = **가까운 적을 축으로 옆으로 2걸음** (호를 따라)
- [x] 각도는 `2 / 거리` 로 저절로 붙는다

| 몹까지 | 도는 각 | 호 | 직선 |
|---|---|---|---|
| 1걸음 | 115° | 2.00 | 1.68 |
| 2걸음 | 57° | 2.00 | 1.92 |
| 3걸음 | 38° | 2.00 | 1.96 |
| 10걸음 | 11° | 2.00 | 2.00 |

> 판단: **각도와 거리가 서로 환산이 안 되는 것이 진짜 문제였다.**
> 시간은 단위가 틱 하나라 다 합쳐지는데, 공간은 축이 둘인데 자가 따로 놀았다.
> 호 길이를 고정하면 이동·회피와 **같은 자로** 잰다.
>
> 덤: 선회가 저절로 **근접 전용 도구**가 된다.
> 멀면 각이 거의 안 바뀌어 쓸모없고, 붙으면 크게 돈다.
> 규칙에 예외를 넣은 게 아니라 기하가 그렇게 만든다.

### 지켜야 할 부등식

```
선회걸음  >  조준각(라디안) × 몹 사거리
```

지금: `30° = 0.524` × `졸개 사거리 3걸음` = **1.57** < **2걸음** ✓ (여유 0.43)

| 조준각 | 필요한 선회 걸음 |
|---|---|
| 1눈금 (30°) | 2 |
| 1.5눈금 (45°) | 3 |
| 2눈금 (60°) | 4 |

- [ ] **조준각을 넓히면 선회 걸음도 같이 올려야 한다.** 안 그러면 선회가 죽는다

> 파생: 조준각이 그대로여도 **사거리가 길어지면** 선회로 못 벗어난다.
> `0.524 × 6걸음 = 3.14` 인데 선회는 2걸음이다.
> 즉 **리치가 긴 근접 몹은 선회로 못 피하고 회피로 거리를 깨야 한다.**
>
> 이것을 "원거리는 회피" 로 일반화하면 **틀린다.** 갈래를 정하는 것은
> 사거리가 아니라 **공격의 모양**이다. 아래 8-2 참고.

## 8-2. 공격은 직사각형 셋 (v2.0.0)

모양이라는 개념을 없앴다. 모든 공격은 **직사각형 세 수**다.

```
앞 fwd · 뒤 bwd · 옆 side      (전부 걸음, 중심에서 가장자리까지)
```

| 공격 | 앞 | 뒤 | 옆 | 피해 |
|---|---|---|---|---|
| 공격 | 4 | 0 | 2 | 3 |
| 사격 | 8 | 0 | 1 | 2 |
| 선풍 | 3 | 3 | 3 | 3 |
| 후려치기(졸개) | 3 | 0 | 1.5 | 2 |
| 쓸어내기(무식한 놈) | 8 | 0 | 1.5 | 5 |

근접·원거리·광역이 **별도 시스템이 아니라 값의 극단**이다.
짧고 넓으면 근접, 길고 좁으면 원거리, 앞뒤가 같으면 사방(`주위 3걸음`).

- [x] `covers()` 가 한 곳에서 판정한다. 축 방향 `-뒤..앞`, 수직 `옆` 이하
- [x] 부채꼴 · 조준각 · 눈금 · 각도를 전부 없앴다. 자는 **걸음 하나**
- [x] 표식도 하나 — 직사각형 (아이소에서는 평행사변형)

### 왜 이렇게 갔나

옛 구조는 자가 둘이었다. 부채꼴은 **각도**, 직선은 **걸음**.
그래서 같은 빔이 거리에 따라 다르게 굴었다 — 멀면 선회로 피해지고 가까이선 안 피해졌다.

> **원인은 모양이 아니라 재는 자였다.**
> 부채꼴(반폭 ∝ 거리)과 직선(반폭 일정)은 **하나의 회피 카드로 동시에 일관될 수 없다.**
> 수직변위가 일정해야 직선에 맞고, 거리에 비례해야 부채꼴에 맞는다. 동시 만족 불가.

그래서 모양 쪽을 하나로 줄였다.

## 8-3. 걸음 카드 셋 (v2.0.0)

이름이 곧 규칙이다. `앞 · 뒤 · 옆` 세 숫자와 카드 셋이 그대로 맞물린다.

| 카드 | 틱 | 걸음 | 하는 일 |
|---|---|---|---|
| **앞걸음** | 2 | 3 | 대상을 향해. 그쪽을 본다 |
| **뒷걸음** | 1 | 4 | 대상 반대로 곧게. 마주 본 채 |
| **옆걸음** | 1 | 2 | 대상 방향에 **수직으로 곧게** |

- [x] 옆걸음은 **호가 아니라 직선**이다
- [x] 접촉거리 **2걸음** (몸통 지름). 둘이 동시에 다가오면 밀어낸다

> 판단: 호로 돌면 걸음이 **안 쌓인다.** `sin(Nθ) ≠ N·sin(θ)` 라서,
> 접촉거리에서 두 번 돌면 축으로 되돌아온다 (실측 0.00).
> 곧게 가면 그대로 쌓인다.

### 이게 도량형 통일의 목적이다

```
옆걸음 걸음 수 × 횟수   vs   그 공격의 옆 값
```

거리도 각도도 삼각함수도 안 들어간다. **걸음 두 수의 뺄셈.**

| 상황 | 판단 | 실측 (거리 2·4·8·14 전부) |
|---|---|---|
| 옆걸음 2 vs 옆 1 | 한 번에 벗어남 | 2.00 > 1 ✓ |
| 옆걸음 2 vs 옆 2 | 아슬아슬 | 정확히 2.00 = 경계 |
| 옆걸음 2 vs 옆 3 | 두 번이면 벗어남 | 1번 2.00 ✗ / 2번 3.4~4.0 ✓ |

**거리를 바꿔도 값이 그대로다.** 이게 옛 구조에서 안 되던 것이다.

### 옆은 절대, 깊이는 상대

```
옆으로 벗어남   옆걸음 > 옆 값                 ← 거리 안 들어감
뒤로 벗어남     현재 거리 + 뒷걸음 > 앞 값       ← 거리 들어감
```

깊이 축이 거리에 달리는 것은 고칠 게 아니다. **거리를 벌리는 일은 원래 지금 거리에 달렸다.**
두 카드의 성격이 갈리는 근거이기도 하다 — 옆걸음은 셈이 필요 없고, 뒷걸음은 지금 거리를 본다.

### 검증

```
세 예시        거리 2/4/8/14 에서 전부 같은 값
누적           접촉거리에서도 두 번이면 3.41 (옛 호는 0.00)
뒷걸음         앞6 빔은 벗어나고, 앞8 빔은 못 벗어난다 (옆걸음뿐)
접촉거리       앞걸음이 2에서 멈춘다. 동시 접근도 밀어내기로 막힌다
표식           미리보기와 실제가 같은 직사각형 값
```

### 아직 안 한 것

- [ ] **공간판 간발** — 가장자리에 아슬아슬하게 걸쳐 피하면 보상.
      시간축이 `간발` 이면 공간축은 **`한 뼘`**. `한 뼘 차이로 피했다`
- [ ] 옆걸음 방향(좌/우)을 떨군 자리로 고르게 하기. 지금은 위협에서 먼 쪽 자동
- [ ] 몹끼리 겹침 밀어내기 (지금은 나와 몹만)

## 9. 소용없음 → 바닥 효과

`✕ 소용없음` 표시는 **"계산해라"는 신호**다. 시원함의 정반대다.

실측한 규모:

| 상황 | 못 쓰는 카드 | 손패 10장 중 |
|---|---|---|
| 몹이 멂 (5.0) | **13/20 = 65%** | **6.5장** |
| 몹이 가까움 (2.0) | 2/20 = 10% | 1.0장 |
| 붙음 (0.6) | 4/20 = 20% | 2.0장 |

멀 때는 쓸 수 있는 게 이동 4 + 대기 3 = **7장뿐**이다.

### 고칠 것 — 카드마다 바닥 효과

조건이 안 맞으면 **약한 대체 효과**로 떨어진다. 죽은 카드가 원천적으로 없어진다.

| 카드 | 조건 안 맞을 때 |
|---|---|
| 공격 | 사거리 밖이면 → **돌진하며 벤다** (1.0 전진) |
| 선풍 | 사거리 밖이면 → 제자리 회전, 방향 정리 |
| 회피 | 위협 없으면 → 그냥 물러남 |
| 선회 | 위협 없으면 → 각도만 바꿈 |

- [ ] 바닥 효과를 넣고 `소용없음` 표시를 최소로 줄인다
- [ ] 남길 표시는 **진짜 아무 일도 안 나는 것**만 (붙었는데 이동 등)

> 같은 카드인데 하나는 벌이고 하나는 시원함이다.
> `✕ 사거리 밖` → **돌진하며 벤다**.

### 겸해서 줄어드는 것

- [ ] 드라이런 미리보기 폐기 — 즉시 해소는 현재 상태만 보면 된다
- [ ] 소용없음 6종 → 1~2종

- [x] 소용없는 카드면 사유
- [x] 그 카드를 떨구는 동안 **실제로 터질 몹**의 부채꼴을 굵게 그린다

> 판단: 이게 없으면 긴 카드는 **도박**이다.
> 4틱짜리를 던질지 말지는 그 4틱에 내가 받을 피해가 정한다.
> 머리로 숫자 세 개를 더하게 만들면 그게 곧 수싸움이다.
>
> 계산은 이미 `dryRun` 이 하고 있었다. 표시만 붙였다.
> 세계를 복사해 그 카드로 틱을 돌려 보고 되돌린다. 규칙을 두 번 쓰지 않는다.

실측 — 졸개 3마리가 붙어 예고 3틱을 띄운 상황:

| 카드 | 틱 | 줄 피해 | 받을 피해 | 적 공격 |
|---|---|---|---|---|
| 회피 | 1 | 0 | **0** | 0회 |
| 공격 | 3 | 3 | **6** | 3회 |
| 선풍 | 4 | **9** | 6 | 3회 |

같은 값(6 피해)에 공격은 3, 선풍은 9를 준다.
**여럿 앞에서는 선풍이 답**이라는 것이 숫자로 드러난다.

- [x] **때릴 때** — 세로로 살짝 늘어났다가 돌아온다 (가로는 조금 줄어든다)
- [x] **맞을 때** — 빨개졌다가 돌아온다
- [x] 나와 몹이 같은 연출을 쓴다
- [ ] 히트스톱 · 화면 흔들림 · 피해 숫자 — 다음 덩어리

> 판단: 사건마다 `누가 때렸나(si)` · `누가 맞았나(ti)` 를 적어 두고,
> 그 열쇠로 연출 시작 시각을 찍는다. 같은 이름의 몹이 셋이어도 안 헷갈린다.

### 공격 범위는 예고에만 (확정)

- [x] **플레이어의 상시 사거리 고리를 없앤다** (지금 늘 떠 있는 옅은 점선)
- [x] 부채꼴은 **공격 예고 중일 때만** 뜬다
- [x] 내 공격이 닿는지는 **손패 hover 미리보기**로 본다

> 판단: 상시 표시를 없애면 화면이 훨씬 깨끗해진다.
> 대신 hover 미리보기가 **선택이 아니라 필수**가 된다.

### 판 상태 표시

- [x] 상단에 `남은 몹 N` · `경과 M틱`
- [x] 타임라인 패널을 걷어내고 무대를 460px 로 키웠다

> 판단: 적이 여덟이면 몹 바 여덟 줄을 겹쳐 읽는 건 과부하다.
> 머리 위 숫자가 지금 타임라인 바보다 **훨씬 읽기 쉽다.**

### 살아남는 표식 어휘

무대 표식은 나와 몹이 **같은 어휘**를 쓴다. 이 원칙은 그대로 간다.

| 카드 | 무대 표식 |
|---|---|
| 이동 · 회피 | 지면 화살표 (방향만 반대) |
| 선회 | 축을 중심으로 한 호 화살표 |
| 공격 | 조준 부채꼴 + 대상까지 선 |
| 선풍 | 온전한 고리 |
| (예정) 빔 | 방향으로 뻗는 띠 |

- 표식은 시뮬 결과에서 뽑는다. 그리는 쪽은 규칙을 다시 계산하지 않는다
- 액터 발밑에 방향 눈금

## 13. 옛 구조에서 무엇이 남고 무엇이 사라졌나

덩어리 A 에서 코드를 통째로 다시 썼다.

### 사라진 것

| 항목 | 이유 |
|---|---|
| 10틱 라운드 | 판은 목표 달성으로 끝난다 |
| 10칸 타임라인 겹쳐 보기 | 보여줄 10틱 창이 없다. 머리 위 숫자가 대신한다 |
| 계획 단계 · 되돌리기 · `행동턴 ▶` 단추 | 던지는 것이 곧 진행이다 |
| 계획 전체 드라이런 | 미래 계획이 없다. 한 카드만 돌려 본다 |
| 상시 사거리 고리 | 예고에만 뜬다 |
| 허수아비 | 졸개로 갈았다 |
| 소용없음 사유 `적 사거리를 못 벗어남` / `적 조준을 못 벗어남` | 하나로 합쳐 `위협을 못 벗어남` |

### 그대로 살아남은 것

- 한 틱 해소 순서 — 이동 계열 먼저, 그다음 공격
- 이동 방향은 행동이 시작하는 틱에 고정
- 접촉거리 0.6, 뚫고 안 지나감
- 방향 · 조준각 · `조준` 스탯 (플레이어만 있음)
- 선회는 대상 축으로 45도, 방향 안 바꿈
- 선풍은 전방위, 방향 안 바꿈, 범위 안 모두 타격
- `가까운` 대상 지정
- 무대 표식 어휘 — 화살표 · 부채꼴 · 호 · 방향 눈금
- 카드 5:7 비율, 덱 · 무덤 무더기
- 뽑기 모션 (던지기 모션은 목적지를 무대로 바꿨다)

### 고친 버그

- **재생 중 머리 위 숫자가 안 움직였다 (v1.1.0)**
  `snap()` 이 `left` 를 안 담아서, `mobHud` 가 살아 있는 몹에서 직접 읽고 있었다.
  재생이 시작될 땐 시뮬이 이미 다 끝나 있으므로 **최종값만** 보였다.
  몹이 곧바로 다음 행동을 고르는 탓에 숫자가 제자리로 튀어,
  "카드를 내도 1틱만 준다" 처럼 보였다. 시뮬은 처음부터 옳았다.
  이제 `snap()` 이 `left` · `kind` · 표식까지 담고 재생은 프레임에서 읽는다.

  ```
  프레임마다: 3 → 2 → 1 → (터지고 새 예고 3)
  ```

### 새로 생긴 것

- 드래그 앤 드롭 · 예측 상자 · 타격 연출 (v1.1.0)
- 공격 예고를 시작할 때 조준하고, 발동까지 굳는다 (v1.0.1)
- `act` — 나와 몹이 같은 그릇을 쓰는 진행 중 행동 (`{kind, ticks, left, mv}`)
- `stepTick()` — 한 틱. 이동 → 발동 → 남은 틱 깎기 → 몹 재선택
- 공격 발동이 **마지막 틱**
- 졸개 · 졸개 AI (사거리 안이면 공격, 밖이면 이동)
- 몹 머리 위 카운트다운 + 체력 막대
- 섬멸 판정 · 승패 오버레이
- 손패 hover 미리보기 (세계를 복사해 돌려 보고 되돌린다)

### 검증한 것 (헤드리스 22항목)

```
틱은 던질 때만 흐른다      그리기만으로는 clock 안 움직임
공격은 마지막 틱에 터진다   1틱째 20 · 2틱째 20 · 3틱째 18
2틱의 회피 창              예고 뜬 뒤 회피 → 안 맞음
졸개는 두 대에 죽는다       6 → 3 → 0
몹이 다가온다              4.6/4.0/5.2 → 1.6/1.0/1.6 (6틱)
미리보기는 세계를 안 건드림  dryRun 전후 상태 동일
섬멸 종료                  몹 0마리 → phase = over
```

v1.0.1 에서 12항목 더:

```
예고 시작 때 조준          90°/180°/-120° 어디를 보고 있어도 나를 조준
예고 뒤엔 안 따라옴        내가 선회해도 몹 방향 그대로 → 빗나감
바보가 아님                빗나간 뒤 새 예고는 내 새 자리를 조준
계속 흘리려면 계속 선회     매 예고마다 선회 → 4번 다 흘림
한 번 돌고 손 놓으면        다음 예고에 맞음 (예전엔 영영 안 맞았음)
선풍은 방향 안 바꿈
```

v1.0.2 대칭 확인:

```
내가 공격 준비 중 몹이 45도 회피  →  빗나감 (몹 체력 6/6)
몹이 공격 준비 중 내가 45도 선회  →  빗나감 (내 체력 20/20)

선풍은 상대가 돌아도 맞음         →  전방위라 각도를 안 본다
미리보기 부채꼴                  →  던졌다면 굳었을 방향을 그린다
```

## 14. 작업 순서

넷이 서로를 지탱한다. 여럿이 있어야 간발이 자동화 안 되고,
즉시 해소여야 숫자 읽기가 즉각적이고, 숫자 하나여야 계산이 안 생긴다.

**1·2·3 은 한 덩어리로 간다.** 쪼개면 중간에 예고를 볼 수 없는 상태가 생긴다.
타임라인 바를 걷어내면서 동시에 머리 위 숫자를 붙여야 화면이 안 빈다.

1. [x] **덩어리 A** — 즉시 해소 + 졸개 3마리 + 머리 위 숫자 + 섬멸 모드
       - 공격 발동을 마지막 틱으로
       - 손패 5장, 던지면 즉시 보충
       - 타임라인 바 철거, 무대 확대
       - 상시 사거리 고리 제거, hover 미리보기
2. [ ] **연출** — 히트스톱 · 흔들림 · 피해 숫자 (늘어남·빨개짐은 v1.1.0 에서 함)
3. [x] **대상 지정** — 떨군 자리가 대상을 정한다 (7-2)
4. [x] **공격의 모양** — `shape` 스탯과 직선 판정 · 직선 표식 · 사격 카드 (8-2)
5. [ ] **값이 다른 몹** — 창잡이(옆 넓게) 사수(앞 길게) 광폭(사방)
