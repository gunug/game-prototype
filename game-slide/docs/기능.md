# 슬라이드

10*10 필드의 안쪽 6*6 을 플레이어가 한 칸씩 움직인다. 고블린이 매 턴 쫓아와 때린다.
게임 규칙 원문과 진행 체크는 [rule.md](rule.md) 에 있다. 여기에는 구현 쪽 결정만 적는다.

# 화면구성
- [x] 한 파일(`index.html`) 안에 판 하나. 스테이지 고르는 화면은 아직 없다
- [x] 상단 바에 `← 목록`, 체력, 턴, 몬스터 수, 소리, `다시`
  - 단추 글자에 `white-space:nowrap`. 안 걸면 `← 목록` 이 두 줄로 접히면서
    상단 바 높이가 통째로 두 배가 된다
  - 470px 밑에서는 게임 이름을 감춘다. 제목보다 체력·턴·단추가 먼저다
- [x] 판 아래에 퀘스트 바 (`.quest`)
  - 판은 1:1 정사각이라 세로로 남는 자리가 생긴다. 거기에 놓는다
- [x] 쓰러지면 판을 흑백으로 낮춘다 (`.play.over .board`)
- [x] 판은 화면 크기에 맞춰 리사이즈
  - 판이 340px 밑으로 좁아지면 칸 간격을 2px → 1px 로 줄인다
- [x] 외부 칸은 내부 칸의 1/3 크기로 그린다 (`OUTER_SCALE`)
  - 외부는 적이 어디서 나오는지만 보여 주면 된다. 남는 자리를 내부가 가져간다.
    430px 폭에서 내부 칸이 43px → 52px 로 커졌다
  - 규칙은 그대로다. 좌표도 이동도 스폰도 안 건드렸다. 화면에서 차지하는 자리만 줄였다
  - 칸마다 크기가 달라 더는 `색인 * 간격` 으로 자리를 못 낸다. `computeAxis()` 가
    한 축의 크기·시작 위치를 미리 배열로 만들고, 가로세로가 그것을 각각 참조한다.
    그래서 왼쪽 띠의 안쪽 행 같은 칸은 좁고 길쭉해진다
  - 내부 칸 C 는 `전체 = 6*C + 4*(C/3) + 간격*9` 를 풀어서 낸다
- [x] 토큰은 늘 정사각형. 칸의 짧은 변에 맞춰 가운데 둔다
  - 좁고 길쭉한 칸을 꽉 채우면 고블린이 길쭉한 알약 바닥에 처박힌 꼴이 된다
  - 가운데로 미는 것은 `left`/`top` 으로 한다. `transform` 은 칸의 원점을 그대로
    가리켜야 자리 계산이 한 군데로 모이고, 테스트도 자리를 되읽을 수 있다
- [x] 내부 6*6 둘레에 노란 테두리
  - 갈 수 있는 범위가 바닥 색만으로는 헷갈려서 경계를 선으로 한 번 더 그렸다
  - 테두리 위치·크기는 `MIN`/`MAX` 에서 계산한다. 외부 줄 수를 바꿔도 따라간다
- [x] 사방이 막히면 안내 문구가 `갇혔다. 다시 를 눌러라` 로 바뀐다
  - 규칙에 없는 것을 넣었다. 승패 규칙이 아직 없어서, 갇히면 어떤 입력도 안 먹는데
    그 상태가 고장인지 규칙인지 화면상 구분이 안 된다

# 그리기
- [x] 칸은 배경으로 깔고, 플레이어·몬스터는 그 위에 얹은 `.token` 으로 둔다
  - 칸의 내용물을 갈아 끼우는 대신 토큰을 `transform` 으로 옮긴다.
    그래야 이동이 애니메이션이 된다 (`transition:transform .13s`)
- [x] 몬스터 등장 효과는 안쪽 `.glyph` 에 건다
  - 토큰 자신의 `transform` 은 좌표를 잡는 데 이미 쓰고 있다.
    거기에 `scale` 애니메이션을 얹으면 몬스터가 판 왼쪽 위로 튀어 나간다

# 스프라이트
- [x] 규격: **64x64, 알파 채널 있는 PNG**. 후처리 없이 그대로 쓴다
  - `images/` 에 넣고 `KINDS` 의 `img` 에 파일 이름만 적으면 끝이다
  - 한때 384px 에 알파 없는 RGB 를 받아서 검정 배경을 잘라 쓰던 시절이 있었다.
    그 후처리는 이제 없다. 새 그림은 처음부터 알파를 갖고 온다
- [x] 토큰 안에 `<img class="glyph">` 로 넣는다
  - 종류별 파일은 `KINDS` 표에만 적혀 있다 (`player.png`, `goblin.png`, `goblin_rider.png`)
- [x] `image-rendering: pixelated`
  - 원본 64px 이 40~70px 로 그려진다. 1:1 언저리라 픽셀 아트는 pixelated 가 또렷하다
  - 384px 원본이던 때는 반대였다. 10배 축소라 픽셀을 왕창 버려 실루엣이 깨졌고,
    그때는 부드럽게 줄이는 쪽이 나았다. 원본 크기가 바뀌면 이 선택도 같이 바뀐다
- [x] 바닥판은 옅은 방사형 그라데이션 + 1px 테두리
  - 스프라이트가 주인공이라 칸을 꽉 채워 칠하면 그림이 안 보인다.
    플레이어는 노란 테, 몬스터는 붉은 테로 누가 누구인지 알린다
- [x] 스프라이트 높이는 토큰의 72% (작은 외부 토큰은 86%)
  - 나머지 아래쪽을 체력 표시 자리로 비워 둔다. 안 그러면 발이 체력바에 겹친다

# 턴
- [x] 한 페이즈 = 민첩 순서로 저마다 한 번씩 → 몬스터 하나 생성
  - 행동은 이동 아니면 공격, 택일이다. 따로 도는 페이즈가 아니다
  - 고블린: 붙어 있으면 `damage()`, 아니면 `goblinStep()`. `goblinAct()` 한 곳에서 고른다
- [x] `actOrder()` 가 플레이어와 몬스터를 한 줄로 세운다
  - `민첩 내림차순, 생성 순서(seq) 오름차순`. 플레이어도 같은 줄에 선다.
    `[player, ...monsters]` 를 그대로 정렬하므로 규칙이 한 군데에만 있다
  - `seq` 는 `nextSeq++` 로 준다. 플레이어가 0, 몬스터가 1부터. `다시` 에서 1 로 되돌린다
- [x] 페이즈는 비동기다. 한 놈이 끝나야 다음 놈이 움직인다
  - `HIT_DELAY` 120ms (돌진 → 피해), `ATTACK_GAP` 260ms (한 대 → 다음 한 대),
    `MOVE_GAP` 130ms (한 걸음 → 다음 걸음)
- [x] 행동 함수가 무엇을 했는지 돌려준다 (`'attack' | 'move' | null`)
  - 부른 쪽이 그에 맞는 만큼 쉰다. 예전에는 "때렸나" 만 boolean 으로 넘겨서
    걸음에는 뜸을 못 들였다
  - `null` 은 막혀서 아무것도 못 한 것. 보여 줄 것이 없으니 안 쉰다.
    막힌 놈까지 세면 벽에 낀 몬스터가 많을수록 한 판이 공연히 길어진다
  - `stepToward`/`stepKnight` 도 실제로 옮겼는지를 돌려주도록 고쳤다
- [x] 몰릴수록 걸음 간격을 좁힌다 (`moveGap()`)
  - `min(MOVE_GAP, max(MOVE_GAP_MIN, MOVE_BUDGET / 마릿수))`.
    10마리가 130ms 씩이면 한 페이즈가 1.5초다. 재 보고 0.9초로 묶었다
  - 실측: 1마리 267ms, 3마리 546ms, 5마리 820ms, 10마리 924ms, 20마리 684ms
    (20마리는 서로 막혀 실제로 걷는 놈이 적다)
  - 상태와 연출을 따로 두지 않았다. 상태를 먼저 다 계산하고 그림만 나중에 그리면
    "지금 체력이 몇인가" 가 두 벌이 되고, 시체가 사라지기 전에 다른 놈이
    그 칸으로 들어오는 것 같은 어긋남을 하나하나 손봐야 한다.
    시간 축을 하나로 두면 그런 것이 안 생긴다
  - 대신 `busy` 로 입력을 막는다. 안 막으면 연출 중에 다음 페이즈가 겹쳐 든다
- [x] `phaseId` 세대로 갈아엎힌 페이즈를 걸러 낸다
  - `다시` 는 `phaseId` 를 올린다. 기다리던 `strike()` 는 깨어나서 세대가
    바뀐 것을 보고 그냥 물러난다. 안 그러면 새 판의 플레이어를 때린다
  - `runPhase` 도 매 단계마다 세대를 확인한다
- [x] 플레이어 행동은 함수로 넘겨 제 차례에 실행한다 (`runPhase(playerAction)`)
  - 입력할 때 정해지지만 실제로 나가는 것은 제 차례다. 그 사이에 더 빠른 몬스터가
    칸을 채우거나 비울 수 있어서, 이동은 제 차례에 `canStep()` 을 다시 본다
  - 다시 봐서 막혔으면 행동만 날아가고 페이즈는 계속 간다.
    입력 시점의 검사(`move()` 첫 줄)는 "페이즈를 시작할지" 를, 제 차례의 검사는
    "이 행동이 아직 되는지" 를 본다. 둘은 다른 질문이다
  - 플레이어가 실제로 움직였을 때만 페이즈가 돈다. 벽이나 몬스터에 막히면
    이동 수도 안 오르고 고블린도 아무것도 안 하고 안 늘어난다.
    벽에 대고 스와이프해서 적만 불리는 일이 없어야 한다
  - 생성은 행동이 아니다. 규칙의 행동 목록에 없어서 페이즈 끝에 따로 둔다
- [x] 인접 판정은 플레이어가 움직인 뒤에 한다
  - 순서가 `플레이어 → 몬스터` 라서 자연히 그렇게 된다. 그 결과 도망친
    페이즈에는 안 맞고, 고블린 쪽으로 다가간 페이즈에는 맞는다
  - 이 때문에 한 마리가 뒤를 쫓기만 하면 처음 한 대 말고는 못 맞힌다.
    플레이어의 이동이 매번 인접을 깨서, 고블린은 계속 이동만 고르게 된다.
    직교 이동만 있으니 인접한 칸에서 다른 인접한 칸으로 갈 방법이 없다
- [x] 칸 차지 판정은 `occupied(x,y)` 하나로 본다
  - 플레이어와 몬스터를 같은 "물체" 로 취급한다. 플레이어 이동, 고블린 이동,
    스폰 자리 고르기가 전부 이 함수를 쓴다. 규칙이 세 군데로 갈라지지 않는다
- [x] 몬스터는 배열 순서대로 한 마리씩 옮긴다
  - 동시에 옮기면 두 마리가 같은 칸을 노릴 때 겹친다. 차례로 옮기면
    `occupied` 가 그때그때 최신이라 겹칠 수가 없다

# 드래프트
- [x] 카드는 `DRAFT_CARDS` 표에. `{id, title, note, img, once, need, fly, bump, apply}`
  - `once` 는 기능형. 가지면 다시 안 나온다. `need` 는 앞에 가져야 할 카드의 id
  - `img` 가 있으면 카드 얼굴에 그림이 붙고(`.d-img`), 고를 때 그 그림이 날아간다
  - `bump` 는 닿았을 때 무엇이 튀느냐다. 날아가 닿는 곳은 늘 아이콘 줄이라,
    `bump:'atk'` 인 수치 카드만 그 딱지를 따로 튀게 한다
  - `fly` 는 그림이 없는 카드가 날릴 글씨. 지금은 다 그림이 있어 안 쓰인다
  - 효과가 `apply` 안에 들어 있어 카드를 늘릴 때 다른 곳은 안 건드린다
  - 구현된 것만 표에 둔다. "현재는 구현된 카드만 등장" 이 저절로 지켜진다
- [x] 카드가 모자라면 같은 카드가 여러 칸에 온다 (`pickCards`)
  - 주머니를 비우면 다시 채우는 식이라, 카드가 넉넉하면 서로 다른 카드가
    나오고 모자라면 중복이 난다. 지금(2장)은 셋 중 한 칸이 겹친다
- [x] 뽑기는 `availableCards()` 가 걸러 준 것에서만 한다
  - `once` 인데 이미 가진 것, `need` 를 아직 못 채운 것을 뺀다.
    `밀치기` 를 가지면 그 자리를 `밀고가기` 가 잇는다 (연계)
  - 가진 것은 `player.cards`(Map). 카드 id → 고른 횟수.
    "가졌나"(`has`)와 "몇 번"(`get`)이 한 자리에 있어 어긋날 수가 없다
  - 카드가 늘어도 표에 `once`/`need` 만 적으면 되고 뽑기는 안 건드린다
  - 누적형(`공격력+5`, `경험치+10%`)은 `once` 가 없으므로 늘 남아 있다.
    그래도 목록이 빌 수 있는 길(언젠가 전부 기능형)이 있어, 빈 목록이면
    `pickCards` 가 빈 손을 돌려주고 `openDraft` 는 안 열고 그냥 넘어간다.
    안 막으면 `undefined` 카드가 판에 깔린다
- [x] 카드를 갖는 곳은 `takeCard()` 하나다
  - 횟수를 적고 `card.apply()` 를 부른다. 세는 곳이 한 곳이라 아이콘 줄의
    로마자와 "가졌나" 판정이 갈라질 수 없다
  - 기능형의 `apply` 는 비어 있다. 가졌다는 사실만으로 동작한다
- [x] 고르는 동안 페이즈가 `await` 로 멈춰 선다
  - `openDraft()` 가 Promise 를 돌려주고 고를 때까지 안 풀린다.
    페이즈 안에서 기다리므로 `busy` 가 켜진 채라 판이 안 움직인다
  - 입력 처리에서 `drafting` 을 `busy` 보다 먼저 본다. 안 그러면 `busy` 에 걸려
    카드도 못 고르고 영영 멈춘다
- [x] 레벨업은 `pendingDrafts` 를 쌓기만 하고, 실제로 고르는 것은 페이즈 끝
  - 경험치는 공격 도중(페이즈 한복판)에 오른다. 거기서 바로 띄우면 남은
    몬스터가 아직 안 움직인 판을 보고 고르게 된다
  - `while (pendingDrafts > 0)` 이라 두 레벨이 오르면 두 번 고른다
- [x] 모달을 게임판과 같은 격자로 짰다
  - 칸은 `aspect-ratio:1`, 모서리 `6%`(판의 3px/52px), 간격은 칸 대비 2/52 로 맞췄다
  - grid 의 `gap:%` 는 격자 전체 너비 기준이라 칸 기준 비율과 다르다.
    `0.0385 / 3.077 = 1.25%` 로 환산해 넣었다. 처음에 3.8% 로 뒀다가
    실측해 보니 칸 대비 0.123 이 나와(판은 0.0385) 세 배 넘게 벌어져 있었다
  - 가운데 칸에는 `.token.player` 를 그대로 세운다. 같은 class 를 쓰므로
    스프라이트·공방 딱지·체력바·경험치바가 저절로 판과 같은 모양이 된다.
    토큰 안 크기는 `em` 이라 `font-size` 하나만 칸 크기에 맞추면 비율이 따라온다
- [x] 레벨업 알림(`announceLevelUp`)은 모달을 열기 전에 `await` 한다
  - 소리는 `playLevelUp()`. 도-미-솔-도를 0.085초씩 늦게 시작해 올라가게 쌓는다.
    휘두르는 소리는 잡음이었지만 이쪽은 음정이 있어야 "올랐다" 로 들린다
  - `LEVELUP_MS`(900ms)는 CSS 의 `levelpop .9s` 와 같아야 한다
- [x] 피격의 붉은 빛은 `::after` 로 한 겹 덮는다
  - `filter: brightness` 만으로는 흰빛이라 무엇에 맞았는지가 아니라 그냥 밝아진
    것으로 보인다. 붉은 겹을 덮으면 색으로 알린다
  - `.token.hit::after` 와 `.d-cell.hit::after` 가 같은 규칙을 쓴다.
    판의 블럭이든 모달의 카드든 맞는 모습이 같다

- [x] 체력 0 인 몬스터는 `killMonster()` 로 목록과 화면에서 같이 지운다
  - `monstersTurn()` 은 사본을 돌고 `hp > 0` 인 놈만 처리한다.
    지금은 몬스터가 제 차례에 죽을 일이 없지만, 목록이 바뀌는 중에 도는 것은 위험하다
- [x] 데미지 숫자는 판에 직접 붙였다 900ms 뒤에 지운다
  - 토큰 안에 두면 안 된다. `.token` 에 `will-change:transform` 이 걸려 있어
    쌓임 맥락이 생기고, 그 안에서는 `z-index` 를 아무리 올려도 옆 토큰 위로 못 나온다.
    판의 자식으로 두고 `z-index:50` 을 준다
  - 자리는 맞은 놈의 칸에서 계산한다. 가로는 칸 가운데, 세로는 칸 위에서 30% 지점
  - 떠오르는 거리는 `em`. `%` 는 글자 상자(16px 남짓) 기준이라 아무리 키워도
    몇 px 밖에 안 올라가서 바로 위 칸 체력바에 겹친 채로 머문다
  - 제일 진한 구간이 제 칸 안에 오게 잡았다. 칸 밖으로 나가는 것은 흐려진 뒤다
  - 글자 크기는 내부 칸 기준(`innerCell * 0.34`, 최소 11px)으로 준다.
    토큰 기준 `em` 으로 하면 외부 띠(17px)에서 3px 로 찍혀 못 읽는다
  - 어디에도 `overflow:hidden` 을 걸지 않았다. 걸면 떠오르다 잘린다

# 소리
- [x] 음원 파일 없이 WebAudio 로 그때그때 만든다
  - 받아 올 것이 없어 한 파일 그대로 돌아간다. 음원을 넣으면 파일이 늘고
    CSP·경로 문제가 붙는다
  - 감쇠하는 잡음 버퍼를 대역 필터(1600Hz → 360Hz)로 훑어 "휘두르는" 소리를 낸다
  - `lunge()` 안에서 낸다. 공격이 지나는 길목이 거기 하나뿐이라 헛치는 것도 같이 잡힌다
- [x] `AudioContext` 는 처음 필요할 때 만들고, 멈춰 있으면 깨운다
  - 브라우저는 사용자가 건드리기 전에는 소리를 막는다. 공격은 늘 입력 뒤라
    그 자리에서 깨워도 된다
  - `AudioContext` 가 없는 환경(검사·오래된 브라우저)에서는 조용히 넘어간다
- [x] 상단 바에 끄고 켜는 단추
  - 끌 방법 없는 소리는 민폐다. 켤 때 한 번 소리를 내서 켜진 것이 들리게 한다
- [x] 상단 바 체력은 `renderHp()` 안에서 같이 고친다
  - `updateStatus()` 는 페이즈 끝에 한 번만 돈다. 거기서만 고치면 한 대씩
    끊어 때리는 동안 상단 바만 옛 값에 머물러, 정작 언제 깎였는지가 안 보인다
- [x] 공격 연출은 `.glyph` 를 방향대로 밀고, 피격 연출은 `.glyph` 를 줄인다
  - 토큰의 `transform` 은 자리를 잡는 데 쓰고 있어서 못 건드린다.
    스프라이트 등장(`pop`), 피격(`struck`), 돌진(`lunge-*`) 이 전부 안쪽 요소에 걸린다
  - `.token.hit .glyph` 는 class 두 개라 `.monster .glyph` 보다 우선한다.
    안 그러면 등장 애니메이션이 피격 애니메이션을 덮는다
- [x] 체력바는 토큰 안에 넣고 `em` 으로 크기를 잡는다
  - 토큰 `font-size` 가 칸 크기에 맞춰 정해지므로, `em` 이면 리사이즈를 따라간다.
    px 로 박으면 작은 화면에서 체력바가 토큰을 덮는다
- [x] 공격력은 토큰 좌상단에 아이콘 하나로
  - 칼 위에 공격력. 색 바탕 대신 아이콘을 깐다
  - 방어력을 없애면서 우상단의 방패 칸도 같이 뺐다. `defMode` 와 방패 그림
    두 장(`defence`, `defence_reflect`)은 코드에서 빠졌다. 파일은 남겨 뒀다
  - 아이콘은 64px 을 19px 로 줄여 쓴다. 4배 축소라 `image-rendering` 은
    기본값(부드럽게)이 낫다. 캐릭터 스프라이트는 1:1 언저리라 `pixelated` 를
    쓰는데, 같은 파일 안에서 배율이 달라 선택도 다르다
  - 은색 아이콘을 19px 로 줄여 쓴다. 뒤에 오는 스프라이트가 어두울 때도(기사)
    밝을 때도(고블린) 있어서 `brightness(1.35)` 로 올리고 검은 그림자로 윤곽을 잡았다
- [x] 아이콘 파일 이름을 뜻대로 맞췄다
  - `attack1`(한번공격) / `attack2`(두번공격). 예전 이름(`onesword`)은 그림 생김새라
    무엇을 뜻하는지가 안 보였다
  - `defence`, `defence_reflect` 는 방어력을 없애면서 안 쓰게 됐다. 파일은 남겨 뒀다
- [x] 어떤 그림을 쓸지는 CSS 가 아니라 상태가 정한다
  - `atkMode`/`defMode` 를 class 로 내리고(`atk-single` 등) CSS 는 class → 파일만 잇는다.
    `renderHp()` 가 체력·공방 숫자와 같은 때에 class 도 갈아 끼운다
  - 파일을 CSS 에 바로 박아 두면 상태가 늘 때마다 CSS 와 JS 를 같이 고쳐야 한다
  - 한 번에 하나만 켜지도록 `classList.toggle` 로 전부 껐다 켠다.
    안 그러면 옛 class 가 남아 두 그림이 겹친다
  - 흰 숫자에는 검은 테를 둘렀다. 은색 아이콘 위에 흰 글씨라 안 그러면 안 읽힌다
  - 값은 `renderHp()` 가 체력과 같이 고친다. 지금은 안 변하는 값이지만
    버프가 들어오면 체력과 같은 때에 갱신되어야 하고, 부르는 곳을 늘리지 않는다
  - 위(공·방) 아래(체력)로 갈라 놓아 서로 안 겹친다.
    가운데는 타격 딱지 자리라 셋이 각자 층을 쓴다
  - `tiny` 토큰에서는 감춘다. 17px 토큰에서 2.5px 로 찍혀 못 읽는다
- [x] 체력 숫자는 체력바 안에 얹는다
  - 52px 칸에 스프라이트·바·숫자를 층층이 쌓을 자리가 없다. 바를 조금 키우고
    (`.22em` → `.42em`) 그 위에 숫자를 겹쳤다. 바는 채움, 숫자는 정확한 값을 맡는다
  - 스프라이트 높이를 86% → 72% 로 줄여 자리를 냈다
  - 외부 띠 토큰은 17px 이라 숫자가 2.7px 로 찍힌다. `tiny` 를 붙여 숫자만 감추고
    바는 남긴다. 문턱은 `TINY_TOKEN` 30px
  - `full` 일 때 숨기던 것을 없앴다. 숫자를 보여 주는 것이 목적이라 늘 떠 있어야 한다
- [x] 피격 표시는 `filter: brightness` 로 낸다
  - `transform` 은 자리를 잡는 데 쓰고 있어 흔들거나 키울 수가 없다.
    같은 이유로 몬스터 등장 효과도 안쪽 글자에만 걸려 있다
  - 연달아 맞을 때 애니메이션이 다시 재생되도록 class 를 뗐다 붙인다
- [x] 고블린 체력은 아직 줄어들 일이 없다
  - 플레이어 공격 규칙이 없다. 그래도 규칙이 "몬스터도 현재/최대 체력" 이라
    값과 체력바는 만들어 뒀다. `damage()` 는 대상을 안 가리므로 그대로 쓸 수 있다

# 입력
- [x] 방향 하나만 받고, 무엇을 할지는 대상 칸이 정한다 (`act()`)
  - 몬스터가 있으면 `attack`, 내부의 빈 칸이면 `move`, 그 외(벽)는 아무 일도 없음
  - 판정이 한 함수에 모여 있어 키와 스와이프가 같은 규칙을 쓴다
  - 긴 스와이프·롱프레스로 공격을 가르던 것은 없앴다. 문턱 상수(`SWIPE_ATTACK`,
    `HOLD_MS`)와 keyup 대기, 잡은 키를 푸는 `blur` 처리가 통째로 사라졌다
- [x] 이동을 `keydown` 에 바로 낸다
  - 짧게·길게를 가를 일이 없어졌다. 뗄 때까지 기다리던 지연도 같이 없어졌다
  - `e.repeat` 는 여전히 무시한다. 꾹 누르면 연출 사이사이로 계속 나가 버린다
- [x] 안내 문구는 `HINT_DEFAULT` 한 곳에 둔다
  - HTML 과 `updateStatus()` 두 군데서 쓴다. 한쪽만 고치면 처음 한 번만 맞고
    첫 턴이 지나는 순간 옛 문구로 돌아간다
- [x] 갇힘 표시를 없앴다
  - 몬스터가 있는 칸이 공격이 되면서, 할 수 있는 것이 하나도 없는 상태가 사라졌다.
    내부 6*6 에서는 어느 칸에 서 있어도 이웃이 최소 둘이고, 그 둘은 빈 칸(이동)
    아니면 몬스터(공격)다. 예전에 둘러싸이면 판이 영영 멈추던 것도 이걸로 없어졌다
