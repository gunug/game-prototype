# 슬라이드

10*10 필드의 안쪽 8*8 을 플레이어가 미끄러져 다니는 프로토타입.
게임 규칙 원문과 진행 체크는 [rule.md](rule.md) 에 있다. 여기에는 구현 쪽 결정만 적는다.

# 화면구성
- [x] 한 파일(`index.html`) 안에 판 하나. 스테이지 고르는 화면은 아직 없다
- [x] 상단 바에 `← 목록`, 이동 수, 몬스터 수, `다시`
- [x] 판은 화면 크기에 맞춰 리사이즈
  - 칸 크기는 `(min(가용 너비, 가용 높이) - 간격) / 10` 을 내림한 정수 px.
    소수 px 이면 격자 선이 칸마다 다르게 뭉개진다
  - 판이 340px 밑으로 좁아지면 칸 간격을 2px → 1px 로 줄인다
- [x] 내부 8*8 둘레에 노란 테두리
  - 플레이어가 어디서 멈추는지가 규칙의 핵심이라, 멈추는 선을 눈에 보이게 뒀다

# 그리기
- [x] 칸은 배경으로 깔고, 플레이어·몬스터는 그 위에 얹은 `.token` 으로 둔다
  - 칸의 내용물을 갈아 끼우는 대신 토큰을 `transform` 으로 옮긴다.
    그래야 슬라이드가 애니메이션이 된다 (`transition:transform .13s`)
- [x] 몬스터 등장 효과는 안쪽 `<span>` 에 건다
  - 토큰 자신의 `transform` 은 좌표를 잡는 데 이미 쓰고 있다.
    거기에 `scale` 애니메이션을 얹으면 몬스터가 판 왼쪽 위로 튀어 나간다

# 조작
- [x] 스와이프는 판이 아니라 `window` 에서 받는다
  - 규칙이 "화면에 어디라도" 이므로. 대신 `a,button` 에서 시작한 것은 무시해서
    상단 바 버튼이 죽지 않게 한다
  - `body{touch-action:none}` 이 있어야 모바일에서 스와이프가 스크롤로 안 샌다
  - `e.target` 이 Element 가 아닐 수도 있어서 `closest` 가 있는지 먼저 본다.
    바로 부르면 `closest is not a function` 으로 조작이 통째로 죽는다
- [x] 방향키와 WASD 도 같이 받는다
- [x] `다시` 는 플레이어를 (4,4) 로, 몬스터·이동 수를 처음 상태로 되돌린다
