# 살아 있는 것들
- [x] 플레이어도 몬스터도 같은 구조체다 (`BEINGS` 표 + `makeBeing()`)
  - 표에 `name, img, atk, def, maxHp, agi` 와 몬스터는 `step` 까지. 종류마다 다른 것이
    전부 여기에만 있다. 새 종류를 넣을 때 손댈 곳이 한 군데다
  - `makeBeing(kind, x, y)` 가 표를 베껴 하나를 만든다. 플레이어도 이걸로 만든다.
    예전에는 플레이어만 객체 리터럴로 따로 적혀 있어서, 스텟이 늘 때마다
    두 군데를 같이 고쳐야 했다
  - 흩어져 있던 `PLAYER_MAX_HP`, `GOBLIN_ATK`, `*_AGI` 상수를 다 걷어냈다
- [x] 이동 방식도 표에 함수로 담는다 (`step`)
  - 고블린은 `stepToward` (상하좌우 한 칸), 라이더는 `stepKnight` (L 자).
    `monsterAct()` 는 "붙었으면 공격, 아니면 `BEINGS[kind].step`" 만 안다
- [x] 라이더는 갈 수 있는 여덟 칸을 점수 매겨 고른다
  - 점수는 `|플레이어와의 거리 - 1|`. 목표가 인접이라 거리 1 이 0점이다
  - 사이 칸은 안 본다. 나이트는 뛰어넘는다

# 전투
- [x] 피해는 `damageTo(때리는 쪽)` 한 곳에서 낸다
  - `Math.max(1, 공격력)`. 방어력을 없애면서 맞는 쪽은 계산에서 빠졌다.
    바닥값 1 은 남겼다. 앞으로 공격력 감쇠 같은 것이 붙으면 여기서 처리한다
  - 위험 표시도 같은 함수를 쓴다. 딱지에 적히는 수와 실제로 깎이는 수가
    어긋날 자리가 없다
  - 검사도 공격력이 아니라 이 함수로 기대값을 낸다. 공격력을 그대로 피해로
    보고 숫자를 박아 두면 스텟이 바뀔 때마다 검사가 우수수 깨진다
- [x] 플레이어 공격은 바로 옆 한 칸. 빈 칸을 쳐도 페이즈는 넘어간다
  - 행동을 쓴 것이기 때문이다. 헛치면 그 턴을 버리는 셈이라 방향이 의미를 갖는다
- [x] 밀치기(`pushLine`)는 때린 다음에 돈다
  - 순서가 뒤바뀌면 맞을 놈이 먼저 밀려 나가 때릴 것이 없어진다.
    맞고 죽은 놈은 `defeat()` 로 이미 빠졌으므로 밀 목록에도 안 들어온다
  - 공격 방향으로 훑다가 빈 칸을 만나면 거기서 끊는다. 붙어 있는 만큼만 민다.
    미는 힘이 앞 놈을 타고 전해지는 것이라 빈 칸은 못 건넌다
  - 때려 죽인 자리도 빈 칸이다. 앞의 적이 그 대에 죽으면 뒤는 안 밀린다.
    죽인 뒤에 밀기 때문에 저절로 그렇게 된다
  - 다 같은 방향으로 같은 칸수만큼 가므로 서로 밟을 일이 없다.
    그래도 먼 놈부터 옮긴다. 읽는 사람이 앞칸 걱정을 안 하게
  - 판 밖으로 나가면 `defeat()`. 때려 잡은 것과 한 함수라 경험치도 퀘스트
    마릿수도 저절로 같이 붙는다
  - 한 칸이다. 기능형이라 쌓이지 않는다 (`player.skills.has('push')` 하나로 끝)
  - 판에서 눈으로 확인할 때는 자리로 보면 안 된다. 밀린 몬스터가 제 차례에
    도로 걸어와서 원래 칸으로 돌아온다. 판 밖으로 밀어내 죽는 것으로 봐야 한다
- [x] 밀고가기는 밀고 난 뒤 `canStep(dx, dy)` 이면 그 칸으로 간다
  - 이동과 같은 함수를 쓰므로 내부 필드·빈 칸 규칙이 저절로 같다.
    판 끝에서 바깥쪽을 치면 적은 밀려 나가지만 플레이어는 안 따라 나간다
  - 빈 칸을 헛친 경우는 위에서 이미 돌아간 뒤라 여기까지 안 온다.
    안 그러면 공격이 곧 이동이 되어 둘의 구분이 사라진다
  - 밀어서 비웠든 때려 죽여서 비웠든 같이 본다. `canStep` 은 지금 판만 보면 된다
  - 방향 퀘스트(`groupDirs`)에는 안 넣었다. 쓴 행동은 공격이다
- [x] 체력 0 인 몬스터는 `killMonster()` 로 목록과 화면에서 같이 지운다
  - `monstersTurn()` 은 사본을 돌고 `hp > 0` 인 놈만 처리한다.
    지금은 몬스터가 제 차례에 죽을 일이 없지만, 목록이 바뀌는 중에 도는 것은 위험하다
- [x] 데미지 숫자는 판에 직접 붙였다 900ms 뒤에 지운다
  - 토큰 안에 두면 안 된다. `.token` 에 `will-change:transform` 이 걸려 있어
    쌓임 맥락이 생기고, 그 안에서는 `z-index` 를 아무리 올려도 옆 토큰 위로 못 나온다.
    판의 자식으로 두고 `z-index:50` 을 준다
  - 자리는 맞은 놈의 칸에서 계산한다. 가로는 칸 가운데, 세로는 칸 위에서 30% 지점
  - 떠오르는 거리는 `em`. `%` 는 글자 상자(16px 남짓) 기준이라 아무리 키워도
    몇 px 밖에 안 올라가서 바로 위 칸 체력바에 겹친 채로 머문다
  - 제일 진한 구간이 제 칸 안에 오게 잡았다. 칸 밖으로 나가는 것은 흐려진 뒤다
  - 글자 크기는 내부 칸 기준(`innerCell * 0.34`, 최소 11px)으로 준다.
    토큰 기준 `em` 으로 하면 외부 띠(17px)에서 3px 로 찍혀 못 읽는다
  - 어디에도 `overflow:hidden` 을 걸지 않았다. 걸면 떠오르다 잘린다

# 돌진 (고블린 대장)

- [x] 상태는 몬스터에 붙은 `m.aim` 하나다. `[dx,dy]` 면 자세를 잡은 것
  - 표에 `charge: true` 가 달린 종류만 자세를 잡는다. 다른 것은 이 길로 안 온다
  - `monsterAct` 는 `m.aim` 이 있으면 무조건 `chargeRun` 이다. 다른 갈래를 안 본다
- [x] `chargePath(m)` 는 자세 방향으로 막힐 때까지의 칸들이다
  - **플레이어를 막는 것으로 안 친다.** 그래야 이 길이 그대로 위험 표시가 된다
    (그 길 위 어디에 서 있든 맞는다)
  - 달릴 때만 플레이어 자리에서 잘라 쓴다 (`findIndex` → `slice`)
- [x] 위험 표시는 `threatDamage` 한 곳에서 본다. 붙어 있는 놈과 같은 표시가 된다
  - **한 놈은 둘 중 하나로만 센다.** 자세를 잡았으면 제 길만 보고 근접은 안 본다.
    둘을 더하면 대장 앞칸이 10 이 아니라 20 으로 떴다 (한 턴에 하나만 하는데도)
  - 칸마다 길을 새로 만든다. 안쪽 25칸 × 몬스터 수라 지금 규모에서는 싸다
- [x] 자세를 잡은 턴은 공격과 같은 만큼 쉰다 (`did === 'aim'`)
  - 걸음만큼만 쉬면 무엇이 일어난 것인지 못 보고 지나간다
- [x] 달리는 동안만 `.dash` 를 붙이고 한 칸의 시간을 `--dash` 로 준다. 끝나면 뗀다
  - 한 칸씩 `place` 하고 그만큼 잔다. 끝 칸으로 한 번에 옮기면 순간이동으로 보인다
  - `per = max(28, 이동시간 / 칸수)`. 검사(`tuning.move = 0`)에서는 0 이라 안 잔다
  - 전환 곡선은 `linear` 다. 칸마다 가속·감속이 붙으면 내달리는 것으로 안 보인다
- [x] 길은 안쪽 필드에서 끝난다. 한 번 안으로 들어온 뒤로는 바깥 띠로 안 나간다
  - 바깥에서 시작한 놈도 안으로 들어올 수 있어야 해서 "들어온 뒤" 로 잰다
