# 위험 표시
- [x] "다음 턴에 맞는 칸" = 지금 몬스터가 바로 옆에 있는 칸
  - 순서가 `플레이어 → 몬스터` 이고, 몬스터는 붙어 있으면 때리고 아니면 옮긴다.
    두 칸 떨어진 놈은 다가오는 데 행동을 써 버려 그 턴에는 못 때린다.
    그래서 판정이 "지금 거리 1" 한 줄로 끝난다
  - 몬스터가 먼저 움직여서 새로 붙는 경우는 없다. 이동과 공격이 택일이기 때문
- [x] 칸 요소를 배열(`cellAt`)로 들고 있는다
  - 매 페이즈 끝에 36칸을 다시 칠한다. 그때마다 `querySelectorAll` 하면
    아까운 데다, 좌표로 바로 집는 편이 읽기도 낫다
- [x] 타격 딱지는 `images/icon/hit.png` 를 배경에 깔고 숫자를 얹는다
  - 한때 12갈래 별을 `clip-path` 두 겹으로 잘라 만들었다. 그림 한 장으로 바꾸면서
    그 CSS 를 다 걷어냈다
  - 그때 배운 것 하나는 남겨 둔다: `clip-path` 를 쓰면 `border` 도 `filter:
    drop-shadow` 도 못 쓴다. 그리는 차례가 `filter → clip-path` 라서 둘 다
    같은 모양으로 잘려 나간다. 지금은 클립을 안 쓰므로 해당 없다
  - 반투명은 딱지 전체 `opacity` 로 건다
  - 흰 숫자에 검은 테를 둘렀다. 붉은 이펙트 위라 안 그러면 안 읽힌다
- [x] 피해량은 `.hit-mark` 딱지 하나로 칸과 플레이어가 같이 쓴다
  - 칸에는 만들 때 하나씩 미리 넣어 두고 글자만 갈아 끼운다. 36칸이 매 페이즈
    다시 칠해지는데 요소를 만들고 지우면 쓸데없이 부산스럽다
  - 플레이어 토큰에도 같은 것을 하나 넣고 `.threatened` 로 여닫는다.
    모양이 한 군데에 있으니 둘이 어긋날 일이 없다
  - 위험하지 않으면 빈 문자열. 숨겨만 두면 남은 숫자가 텍스트 선택이나
    개발자 도구에서 유령처럼 보인다
- [x] 글자 크기는 칸 크기의 30% (`HIT_MARK_SCALE`)
  - 칸에는 `layout()` 이 px 로 넣는다. `em` 으로 두면 기준이 될 font-size 가 칸에 없다
  - 플레이어 것은 `--mark` 사용자 지정 속성으로 준다. 토큰의 font-size 는
    체력바가 쓰고 있어서(0.55배) 딱지가 같이 끌려간다
  - 창 크기가 바뀌면 `layout()` 이 `renderDanger()` 를 다시 불러 딱지도 따라간다.
    안 부르면 칸만 커지고 딱지는 옛 크기로 남는다
- [x] 보일 때의 불투명도는 `--danger-alpha`(.6) 한 곳에서 준다
  - 칸 색과 타격 딱지가 같은 변수를 본다. 한쪽만 고쳐 어긋날 자리가 없다
  - 칸에 `opacity` 를 걸면 안 된다. 바탕(`--surface-soft`)까지 같이 흐려져
    이웃 칸보다 어두워진다. 붉은 색만 `linear-gradient` 로 한 겹 겹쳐 깔고
    그 색을 반투명으로 둔다
  - 그래서 칸의 위험 표시는 `background-color` 가 아니라 `background-image` 다.
    색으로 재려 들면 안 잡힌다 (검사에서 한 번 걸렸다)
- [x] 페이즈가 도는 동안에는 `board.hide-danger` 로 통째로 감춘다
  - 페이즈 시작에 class 를 붙이고 `DANGER_FADE`(90ms) 를 기다린 뒤 첫 행동을 낸다.
    "이동 전에 투명화" 를 지키려면 사라질 시간을 실제로 줘야 한다
  - 끝에서 `updateStatus()` 가 새 상태를 계산한 다음 class 를 뗀다.
    감춰진 채로 다시 칠하므로 옮기는 도중의 어정쩡한 그림이 안 보인다
  - CSS 의 `.09s` 와 JS 의 `DANGER_FADE` 가 같아야 한다. 어긋나면 다 사라지기 전에
    첫 걸음이 나가거나, 다 사라진 뒤에도 더 기다린다
  - class 를 떼는 것은 `finally` 에 둔다. 중간에 빠져나가도 감춘 채로 안 남는다.
    `다시` 도 따로 떼어 준다 (그쪽은 페이즈를 통째로 갈아엎으므로)
- [x] `updateStatus()` 안에서 같이 고친다
  - 페이즈 끝(스폰까지 끝난 뒤)과 `다시` 에서 부르는 한 곳이라, 표시가
    실제 상태보다 뒤처질 자리가 없다
