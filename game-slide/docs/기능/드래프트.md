# 드래프트
- [x] 카드는 `DRAFT_CARDS` 표에. `{id, title, note, img, once, need, fly, bump, apply}`
  - `once` 는 기능형. 가지면 다시 안 나온다. `need` 는 앞에 가져야 할 카드의 id
  - `img` 가 있으면 카드 얼굴에 그림이 붙고(`.d-img`), 고를 때 그 그림이 날아간다
  - `bump` 는 닿았을 때 무엇이 튀느냐다. 날아가 닿는 곳은 늘 아이콘 줄이라,
    `bump:'atk'` 인 수치 카드만 그 딱지를 따로 튀게 한다
  - `fly` 는 그림이 없는 카드가 날릴 글씨. 지금은 다 그림이 있어 안 쓰인다
  - 효과가 `apply` 안에 들어 있어 카드를 늘릴 때 다른 곳은 안 건드린다
  - 구현된 것만 표에 둔다. "현재는 구현된 카드만 등장" 이 저절로 지켜진다
- [x] 카드가 모자라면 같은 카드가 여러 칸에 온다 (`pickCards`)
  - 주머니를 비우면 다시 채우는 식이라, 카드가 넉넉하면 서로 다른 카드가
    나오고 모자라면 중복이 난다. 지금(2장)은 셋 중 한 칸이 겹친다
- [x] 뽑기는 `availableCards()` 가 걸러 준 것에서만 한다
  - `once` 인데 이미 가진 것, `need` 를 아직 못 채운 것을 뺀다.
    `밀치기` 를 가지면 그 자리를 `밀고가기` 가 잇는다 (연계)
  - 가진 것은 `player.cards`(Map). 카드 id → 고른 횟수.
    "가졌나"(`has`)와 "몇 번"(`get`)이 한 자리에 있어 어긋날 수가 없다
  - 카드가 늘어도 표에 `once`/`need` 만 적으면 되고 뽑기는 안 건드린다
  - 누적형(`공격력+5`, `경험치+10%`)은 `once` 가 없으므로 늘 남아 있다.
    그래도 목록이 빌 수 있는 길(언젠가 전부 기능형)이 있어, 빈 목록이면
    `pickCards` 가 빈 손을 돌려주고 `openDraft` 는 안 열고 그냥 넘어간다.
    안 막으면 `undefined` 카드가 판에 깔린다
- [x] 카드를 갖는 곳은 `takeCard()` 하나다
  - 횟수를 적고 `card.apply()` 를 부른다. 세는 곳이 한 곳이라 아이콘 줄의
    로마자와 "가졌나" 판정이 갈라질 수 없다
  - 기능형의 `apply` 는 비어 있다. 가졌다는 사실만으로 동작한다
- [x] 고르는 동안 페이즈가 `await` 로 멈춰 선다
  - `openDraft()` 가 Promise 를 돌려주고 고를 때까지 안 풀린다.
    페이즈 안에서 기다리므로 `busy` 가 켜진 채라 판이 안 움직인다
  - 입력 처리에서 `drafting` 을 `busy` 보다 먼저 본다. 안 그러면 `busy` 에 걸려
    카드도 못 고르고 영영 멈춘다
- [x] 레벨업은 `pendingDrafts` 를 쌓기만 하고, 실제로 고르는 것은 페이즈 끝
  - 경험치는 공격 도중(페이즈 한복판)에 오른다. 거기서 바로 띄우면 남은
    몬스터가 아직 안 움직인 판을 보고 고르게 된다
  - `while (pendingDrafts > 0)` 이라 두 레벨이 오르면 두 번 고른다
- [x] 모달을 게임판과 같은 격자로 짰다
  - 칸은 `aspect-ratio:1`, 모서리 `6%`(판의 3px/52px), 간격은 칸 대비 2/52 로 맞췄다
  - grid 의 `gap:%` 는 격자 전체 너비 기준이라 칸 기준 비율과 다르다.
    `0.0385 / 3.077 = 1.25%` 로 환산해 넣었다. 처음에 3.8% 로 뒀다가
    실측해 보니 칸 대비 0.123 이 나와(판은 0.0385) 세 배 넘게 벌어져 있었다
  - 가운데 칸에는 `.token.player` 를 그대로 세운다. 같은 class 를 쓰므로
    스프라이트·공방 딱지·체력바·경험치바가 저절로 판과 같은 모양이 된다.
    토큰 안 크기는 `em` 이라 `font-size` 하나만 칸 크기에 맞추면 비율이 따라온다
- [x] 레벨업 알림(`announceLevelUp`)은 모달을 열기 전에 `await` 한다
  - 소리는 `playLevelUp()`. 도-미-솔-도를 0.085초씩 늦게 시작해 올라가게 쌓는다.
    휘두르는 소리는 잡음이었지만 이쪽은 음정이 있어야 "올랐다" 로 들린다
  - `LEVELUP_MS`(900ms)는 CSS 의 `levelpop .9s` 와 같아야 한다
- [x] 피격의 붉은 빛은 `::after` 로 한 겹 덮는다
  - `filter: brightness` 만으로는 흰빛이라 무엇에 맞았는지가 아니라 그냥 밝아진
    것으로 보인다. 붉은 겹을 덮으면 색으로 알린다
  - `.token.hit::after` 와 `.d-cell.hit::after` 가 같은 규칙을 쓴다.
    판의 블럭이든 모달의 카드든 맞는 모습이 같다
- [x] 고른 카드에도 `hit` 을 붙인다. 카드를 다시 그릴 때 지운다
  - 안 지우면 지난번에 고른 카드가 붉은 자국을 단 채 다음 드래프트에 다시 나온다
    (검사에서 걸렸다)
- [x] 고르면 판에서 때릴 때와 같은 `lunge()` 를 그대로 쓴다
  - 연출용 함수를 따로 만들지 않는다. 같은 함수라 모션도 소리도 저절로 같다
  - 모달 안 블럭도 `.token.player` 라 `atk-*` class 가 그대로 먹는다
  - `LUNGE_MS`(200ms)는 CSS 의 `lunge-* .2s` 와 같아야 한다. 어긋나면 모션이
    덜 끝난 채로 수치가 날아가거나, 끝나고도 공연히 기다린다
- [x] 순서는 친다 → 날아간다 → 오른다
  - 규칙이 "치는 모션 이후에 카드가 적용" 이라 `card.apply()` 를 맨 뒤로 뒀다
- [x] 고른 카드가 블럭 쪽으로 날아간 뒤에 실제로 붙는다 (`flyToStat`)
  - 시작·도착 자리를 `getBoundingClientRect` 로 재서 `transform` 으로 민다
  - 한 프레임 뒤에 목적지를 넣어야 전환이 걸린다. 같은 프레임에 넣으면
    브라우저가 시작값을 못 봐서 그냥 순간이동한다 (`requestAnimationFrame` 두 번)
  - 값을 바꾸는 것은 날아간 뒤다. 규칙이 "사라진 후 실제로 올라간다" 이므로
    `card.apply()` 를 애니메이션 뒤로 미뤘다
  - 목적지와 글씨는 카드가 정한다. `밀치기` 처럼 딱지에 적을 수치가 없는 카드는
    블럭 자체로 날아가고, 딱지 대신 블럭이 튄다 (`.draft-token.bump`).
    `+5` 를 박아 두었을 때는 밀치기를 골라도 공격력 쪽으로 `+5` 가 날아갔다
  - 날아가는 동안 `drafting.busy` 로 잠근다. 안 잠그면 두 장을 고를 수 있다
- [x] `다시` 는 스텟을 `BEINGS` 표에서 다시 베낀다
  - 드래프트로 올린 공격력·가진 카드가 판을 넘어 남으면 안 된다.
    `BEINGS` 에 없는 것(`cards`, `expBonus`)은 손으로 비워 준다
- [x] 블럭의 아이콘 줄은 `renderSkillRow(블럭)`
  - `DRAFT_CARDS` 표 순서대로 돈다. 고른 순서로 하면 카드를 가질 때마다
    자리가 흔들려 어디에 뭐가 있었는지를 다시 찾아야 한다
  - 누적 횟수는 `roman()`. 표를 두지 않고 식이라 레벨처럼 끝이 없다
  - 로마자는 검은 딱지 위에 노란 글씨다. 검은 테를 두른 맨 글씨로 뒀더니
    획이 가는 `I` 가 테에 먹혀 검은 덩어리로 보였다
  - `i` 에는 `font-size` 를 안 준다. 주면 `width:.46em` 이 제 글씨 기준이 되어
    그림까지 같이 줄어든다. 숫자 쪽만 작은 `em` 을 쓴다
  - 판 위 블럭과 모달 안 블럭이 같은 규칙(`.player .skill-row`)을 탄다.
    `renderSkills()` 가 지금 떠 있는 `.player` 를 다 훑어 같이 그린다.
    모달이 안 떠 있으면 판 위 것 하나뿐이라 저절로 하나만 그린다
  - 크기는 `--sk`(.23em) 하나로 잡는다. 숫자도 이 값을 따라간다
  - 숫자는 그림 위 오른아래 귀퉁이에 얹는다. 세 번 자리를 옮겼다.
    검은 딱지를 깔았더니 그림을 절반으로 줄인 뒤로는 딱지가 그림만 해져서
    칼인지 구슬인지 알아볼 수 없었고, 옆에 세웠더니 이웃 그림과 겹쳤다.
    딱지를 걷고 맨 글씨에 검은 윤곽만 둘렀다. 획 사이로 그림이 비친다
  - `right` 로 붙여 두어 긴 숫자(`XVIII`)는 제 그림 위로 왼쪽으로 자란다.
    `left` 로 붙이면 이웃 쪽으로 뻗는다
  - 줄은 왼쪽부터 채운다. 가운데 정렬이면 카드를 가질 때마다 이미 있던
    그림들이 옆으로 밀려 어디에 뭐가 있었는지를 다시 찾아야 한다
  - 띄우는 높이는 `--sk` 가 아니라 체력바 높이(.38em)를 넘긴 값이다.
    그림 크기로 띄우면 그림을 줄일 때 줄이 체력바 위로 내려앉는다
