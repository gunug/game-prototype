# 입력
- [x] 방향 하나만 받고, 무엇을 할지는 대상 칸이 정한다 (`act()`)
  - 몬스터가 있으면 `attack`, 내부의 빈 칸이면 `move`, 그 외(벽)는 아무 일도 없음
  - 판정이 한 함수에 모여 있어 키와 스와이프가 같은 규칙을 쓴다
  - 긴 스와이프·롱프레스로 공격을 가르던 것은 없앴다. 문턱 상수(`SWIPE_ATTACK`,
    `HOLD_MS`)와 keyup 대기, 잡은 키를 푸는 `blur` 처리가 통째로 사라졌다
- [x] 이동을 `keydown` 에 바로 낸다
  - 짧게·길게를 가를 일이 없어졌다. 뗄 때까지 기다리던 지연도 같이 없어졌다
  - `e.repeat` 는 여전히 무시한다. 꾹 누르면 연출 사이사이로 계속 나가 버린다
- [x] 대기는 행동 셋째다 (`waitTurn`)
  - `runPhase` 를 그대로 쓴다. 플레이어가 아무것도 안 할 뿐 페이즈는 똑같이 돈다
  - 스페이스는 `keydown` 맨 앞에서 가른다. 방향 표(`DIRS`)에 넣으면 방향이 없어서
    `act()` 를 못 부른다
  - 누르고 있기는 스와이프와 같은 자리(`window`)에서 받는다. 판 위든 정보영역이든
    상단 바 빈 곳이든 다 된다. 시작 자리로 조작을 가르면 규칙이 둘이 된다
  - `pointerdown` 에서 3초 타이머를 걸고, `pointermove` 가 문턱의 절반만 넘어도
    지운다. 스와이프와 겹치면 둘 다 나가 버린다
  - 테는 기사에 두른다. 어디를 눌렀든 기다리는 것은 기사다
- [x] 브라우저 기본 길게 누르기를 막는다. 안 막으면 3초를 채우기 전에 끊긴다
  - 길게 누르면 브라우저가 먼저 제 일을 한다: 오른쪽 단추 메뉴, iOS 의
    사진 저장 말풍선, 그림 끌기. 셋 다 그 순간 `pointercancel` 을 날린다
  - `contextmenu`·`dragstart`·`selectstart` 를 막고, `-webkit-touch-callout:none`
    과 `img{-webkit-user-drag:none}` 을 건다
  - 링크·단추·입력칸 위에서는 그대로 둔다. 거기서는 브라우저 기본이 더 쓸모 있다
  - 진짜 `pointercancel`(손가락이 화면을 벗어남)은 그대로 취소로 둔다
  - 타이머가 터지면 `holdFired` 를 세워 둔다. 안 그러면 손을 뗄 때 짧은 누름(탭)
    으로 한 번 더 잡혀 인스펙터가 같이 뜬다
- [x] 안내 문구는 `HINT_DEFAULT` 한 곳에 둔다
  - HTML 과 `updateStatus()` 두 군데서 쓴다. 한쪽만 고치면 처음 한 번만 맞고
    첫 턴이 지나는 순간 옛 문구로 돌아간다
- [x] 갇힘 표시를 없앴다
  - 몬스터가 있는 칸이 공격이 되면서, 할 수 있는 것이 하나도 없는 상태가 사라졌다.
    내부 6*6 에서는 어느 칸에 서 있어도 이웃이 최소 둘이고, 그 둘은 빈 칸(이동)
    아니면 몬스터(공격)다. 예전에 둘러싸이면 판이 영영 멈추던 것도 이걸로 없어졌다

# 조작
- [x] 스와이프는 판이 아니라 `window` 에서 받는다
  - 규칙이 "화면에 어디라도" 이므로. 대신 `a,button` 에서 시작한 것은 무시해서
    상단 바 버튼이 죽지 않게 한다
  - `body{touch-action:none}` 이 있어야 모바일에서 스와이프가 스크롤로 안 샌다
  - `e.target` 이 Element 가 아닐 수도 있어서 `closest` 가 있는지 먼저 본다.
    바로 부르면 `closest is not a function` 으로 조작이 통째로 죽는다
- [x] 방향키와 WASD 도 같이 받는다
- [x] `다시` 는 플레이어를 (4,4) 로, 몬스터·이동 수를 처음 상태로 되돌린다

- [x] 붙잡는 강조(`holdFocus`) 중에는 게임 입력을 다 돌려보낸다
  - `keydown` 은 맨 앞에서 돌아선다. 게임 키가 아니면 `preventDefault` 도 안 한다
    (브라우저 단축키까지 먹으면 안 된다)
  - `pointerdown` 에서 돌아서므로 스와이프도 3초 누르기도 시작조차 안 한다.
    `pointerup` 에도 같은 빗장을 하나 더 둔다 — 강조가 손가락을 내린 뒤 걸릴 수도 있다
  - 예외는 강조된 단추가 하는 일과 같은 키 하나다 (`대기` 강조 중의 스페이스)
