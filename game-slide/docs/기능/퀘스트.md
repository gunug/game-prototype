# 퀘스트
- [x] 퀘스트는 묶음(`QUEST_GROUPS`)이고, 묶음이 항목을 여럿 갖는다
  - 방향 넷은 한 묶음. 그래서 네 줄이 한꺼번에 뜨고 각각 따로 체크된다
  - 출현 규칙(`spawn`)은 항목이 아니라 묶음에 붙인다. 항목마다 두면 고블린과
    라이더가 겹쳐 나오게 된다
- [x] 항목은 세는 방식만 다르고 그리는 쪽은 하나다
  - `dir` 은 움직인 방향 Set 에 들어 있는지, `kill` 은 종류별 잡은 수.
    `itemProgress()` 가 둘을 하나로 덮어서 줄은 한 가지만 안다
  - 방향은 실제로 이동에 성공했을 때만 담는다. 벽에 막힌 입력은 안 센다
  - 잡은 수는 종류별로 다 센다(`groupKills`). 지금 묶음이 안 세는 종류라도
    세어 두면 나중에 "둘 다 잡기" 같은 묶음을 그대로 얹을 수 있다
- [x] 줄은 묶음이 바뀔 때 새로 만든다 (`buildQuestRows`)
  - 묶음마다 항목 수가 다르다. 만들어 두고 값만 갈아 끼우면 4개 → 1개로
    바뀔 때 남은 줄이 유령처럼 남는다
- [x] 한 번에 끝나는 항목은 막대를 감춘다 (`.binary`)
  - 체크와 같은 말을 반복한다. 여러 번 걸리는 항목만 막대가 정보를 준다
- [x] 넘어가는 것은 페이즈 안에서 `await` 한다
  - `advanceQuest()` 가 0.9초 기다리는 동안 `busy` 가 켜져 있어 입력이 막힌다.
    깬 것을 눈이 따라올 시간을 주면서, 그 사이 다음 페이즈가 겹쳐 들지 않는다
  - `phaseId` 를 확인해서 기다리는 사이 `다시` 를 누르면 넘어가지 않는다
- [x] `다시` 는 `startGroup(지금 묶음)` 으로 그 묶음만 되돌린다

# 튜토리얼 묶음

- [x] 묶음에 `burst` 를 붙이면 뜨는 그 자리에서 그만큼 한꺼번에 낸다
  - `startGroup()` 에서 낸다. `questSpawn()` 은 턴마다 부르는 것이라
    `every` 가 있는 묶음만 본다 (`burst` 는 거기서 빠진다)
  - 남은 마릿수 표시도 `every` 가 있을 때만 붙인다. 한꺼번에 낸 묶음은 남은 것이 없다
- [x] 묶음에 `blink: '<단추 id>'` 를 붙이면 뜰 때 그 단추를 붙잡아 강조한다
  - 누를 때까지 깜빡이고, 그동안 나머지는 어두워지고 다른 조작은 안 먹는다
    ([[규칙/UI와-조작|UI와 조작]] 의 붙잡는 강조)
  - 새로 배울 조작이 있는 묶음에만 붙인다. 늘 깜빡이면 배경이 된다
- [x] 묶음에 `hold: true` 면 저절로 안 넘어간다. `종료` 를 눌러야 끝난다
  - `groupDone()` 이 `hold` 묶음을 늘 "안 깬 것" 으로 돌려준다.
    깰 항목이 없어서(`items: []`) 그냥 두면 뜨자마자 넘어가 버린다
  - `종료`(`#act-quit`)는 보통 `그만둘까` 를 띄우지만 `hold` 묶음에서는
    `게임 클리어` 를 띄운다
  - 퀘스트 카드는 `완료` 로 적고 다 깬 색(`all-done`)을 입는다
  - `다시` 는 `hold` 묶음에 와 있으면 묶음 1부터 준다

- [x] `spawn` 은 하나여도 되고 배열이어도 된다. `spawnRules(g)` 가 늘 배열로 준다
  - 센 마릿수(`groupSpawned`)도 규칙마다 따로다. 하나로 세면 대장 한 마리가
    궁수 몫을 먹어 다섯이 다 안 나온다
  - 퀘스트 바의 `남은 출현` 은 턴마다 나오는 규칙들의 남은 수를 합친 것이다.
    한꺼번에 낸 규칙은 남은 것이 없어 셈에 안 든다
