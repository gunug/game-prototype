# 퀘스트
- [x] 퀘스트는 묶음(`QUEST_GROUPS`)이고, 묶음이 항목을 여럿 갖는다
  - 방향 넷은 한 묶음. 그래서 네 줄이 한꺼번에 뜨고 각각 따로 체크된다
  - 출현 규칙(`spawn`)은 항목이 아니라 묶음에 붙인다. 항목마다 두면 고블린과
    라이더가 겹쳐 나오게 된다
- [x] 항목은 세는 방식만 다르고 그리는 쪽은 하나다
  - `dir` 은 움직인 방향 Set 에 들어 있는지, `kill` 은 종류별 잡은 수.
    `itemProgress()` 가 둘을 하나로 덮어서 줄은 한 가지만 안다
  - 방향은 실제로 이동에 성공했을 때만 담는다. 벽에 막힌 입력은 안 센다
  - 잡은 수는 종류별로 다 센다(`groupKills`). 지금 묶음이 안 세는 종류라도
    세어 두면 나중에 "둘 다 잡기" 같은 묶음을 그대로 얹을 수 있다
- [x] 줄은 묶음이 바뀔 때 새로 만든다 (`buildQuestRows`)
  - 묶음마다 항목 수가 다르다. 만들어 두고 값만 갈아 끼우면 4개 → 1개로
    바뀔 때 남은 줄이 유령처럼 남는다
- [x] 한 번에 끝나는 항목은 막대를 감춘다 (`.binary`)
  - 체크와 같은 말을 반복한다. 여러 번 걸리는 항목만 막대가 정보를 준다
- [x] 넘어가는 것은 페이즈 안에서 `await` 한다
  - `advanceQuest()` 가 0.9초 기다리는 동안 `busy` 가 켜져 있어 입력이 막힌다.
    깬 것을 눈이 따라올 시간을 주면서, 그 사이 다음 페이즈가 겹쳐 들지 않는다
  - `phaseId` 를 확인해서 기다리는 사이 `다시` 를 누르면 넘어가지 않는다
- [x] `다시` 는 `startGroup(지금 묶음)` 으로 그 묶음만 되돌린다
