# 스테이지

지역을 고르고, 그 안에서 논다. 판은 하나뿐이고 위에 무엇이 서 있느냐만 다르다.

- [x] 화면은 둘이다: `mode` 가 `select` 면 고르는 화면, `play` 면 스테이지 안
  - 판·격자·이동·공격은 한 벌이다. 고르는 화면도 같은 판을 쓴다.
    화면을 따로 만들면 조작이 둘이 되고, 그러면 "공격해서 고른다" 가 안 된다
- [x] `STAGES` 표 하나에 이름·그림·자리·블로커 수·퀘스트·버티기 규칙이 다 있다
  - 새 지역을 넣을 때 손댈 곳이 한 군데다. `BEINGS` 와 같은 생각이다
  - 퀘스트 묶음도 스테이지가 갖는다. 전역 `QUEST_GROUPS` 는 `FOREST_QUESTS` 가
    되어 고블린 숲 밑으로 들어갔다. `questGroups()` 가 지금 스테이지 것을 내준다
- [x] 들어가고 나오기 (`enterStage` / `gotoSelect`)
  - 들어갈 때마다 판을 걷어 내고(`clearBoard`) 기사를 표에서 다시 베낀다
    (`resetPlayer`). 레벨·업그레이드·코인도 다 처음으로 돌아간다
  - 잠긴 지역은 `enterStage` 가 `false` 를 내고 아무 일도 안 한다
- [x] `다시` 는 지금 퀘스트 묶음부터 다시 (`startStage(groupIndex)`)
  - 블로커는 다시 깔린다. 자리가 매번 다르다
- [x] 상단 바에 `지역` 단추. 고르는 화면에서는 감춘다
  - `.btn` 의 `display:inline-flex` 가 `[hidden]{display:none}` 을 이긴다.
    `.topbar .btn[hidden]` 를 따로 적어 줘야 감춰진다 (드래프트 모달과 같은 함정)

# 기물

- [x] `props` 배열 하나에 블로커와 스테이지 블럭이 같이 산다
  - 둘 다 "칸을 차지하고 살아 있지 않은 것" 이다. 다른 점은 쳤을 때뿐이다
- [x] 막는 자리는 `occupied()` 한 곳이다
  - 여기에 기물을 넣으면 플레이어도 고블린도 라이더도 한꺼번에 막힌다.
    이동 판정이 이미 이 함수 하나로 모여 있어서 손댈 곳이 한 줄이었다
- [x] 밀치기는 기물에 막히면 그 줄 전체가 안 밀린다
  - 판 밖은 다르다. 밖으로 나가는 것은 죽는 것이라 막힌 것이 아니다
- [x] 블로커는 시작 자리와 그 옆 네 칸을 피해서 깔린다
  - 처음부터 갇히면 아무것도 못 한다. 튜토리얼(사방으로 한 번씩 움직이기)도
    첫 수는 늘 난다
- [x] 기물은 체력바가 없으니 스프라이트가 칸을 거의 다 쓴다 (`.prop .glyph{height:88%}`)
- [x] 인스펙터도 기물을 본다 (`renderInspectProp`)
  - 체력·공격 대신 이름·설명, 지역이면 잠김 여부와 블로커 수·퀘스트 묶음 수

# 최고 기록

- [x] 버티기 스테이지에만 있다. 몇 턴 버텼는가가 곧 기록이다 (`bests` / `recordBest`)
- [x] 남기는 자리는 `clearBoard()` 와 `showEnd()` 둘이다
  - 판이 끝나는 길이 그 둘뿐이다. 죽어서 팝업이 뜨든, `지역`·`다시` 로 걷어 내든
  - `max` 로만 올리므로 두 번 불려도 값이 안 흔들린다
  - `gotoSelect()` 는 `clearBoard()` 를 먼저 부른다. `stageIndex` 를 먼저 지우면
    어느 스테이지의 기록인지 알 수가 없다 (한 번 그렇게 놓쳤다)
- [x] `localStorage` 는 막혀 있을 수 있다(사생활 보호 창). `try` 로 감싸고,
      막혔으면 그 판에서만 기억한다. 못 남겨도 게임은 돈다
- [x] 읽은 값은 `bests` 에 담아 둔다. 갱신도 이쪽을 같이 고치므로 늘 맞다

# 지역 블럭의 글자

- [x] 이름은 블럭 위쪽, 기록은 오른쪽 아래 1/4 칸
  - 둘 다 `em` 이라 칸이 커지면 같이 커진다. 토큰의 `font-size` 가 칸을 따라간다
  - 이름은 어두운 그라데이션 위에 흰 글씨. 그림이 밝든 어둡든 읽힌다
  - 기록은 노란 숫자에 검은 테. 그림 위에 바로 얹혀도 읽힌다
- [x] `tiny` 토큰에서는 둘 다 감춘다. 17px 에서는 어차피 안 읽힌다

# 무한의 아레나

- [x] 단계는 `floor(스테이지턴 / 10)`. 스테이지 턴은 퀘스트 턴과 따로 센다
  - 퀘스트 턴(`groupTurns`)은 묶음마다 0 으로 돌아간다. 탑은 묶음이 없으므로
    제 턴(`stageTurns`)이 따로 있어야 한다
- [x] 스텟 배수는 곱으로 쌓는다: `1.1^단계`
  - **새로 나오는 놈에게만 먹인다.** 판에 있는 놈은 안 건드린다.
    그래서 계산이 `makeBeing` 한 곳에서 끝난다
  - 나올 때 한 번 반올림해서 정수로 굳힌다. 실수로 들고 다니다 표시만
    반올림하면 12.1/13.2 같은 체력이 안쪽에 남는다
  - 라이더(체24)는 10턴에 26, 20턴에 29
- [x] 생성 주기는 `max(1, round(기본 * 0.9^단계))`
  - 고블린(3턴): 0~19턴 3턴, 20~59턴 2턴, 70턴부터 1턴
  - 주기가 바뀌면 나오는 박자도 어긋난다. `(턴 - 시작턴) % 주기` 라
    단계가 바뀌는 순간 한 박자 당겨지거나 밀릴 수 있다. 버티기라 문제 없다
- [x] 0턴에도 나온다. 들어가는 순간 `endlessSpawn()` 을 한 번 부른다
- [x] 총 마릿수 제한이 없다. 퀘스트의 `max` 같은 것이 없다
