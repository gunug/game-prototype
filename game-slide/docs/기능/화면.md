# 화면구성
- [x] 한 파일(`index.html`) 안에 판 하나. 스테이지 고르는 화면은 아직 없다
- [x] 상단 바에 `← 목록`, 레벨, 코인, 체력, 턴, 몬스터 수, 소리, `다시`
  - 단추 글자에 `white-space:nowrap`. 안 걸면 `← 목록` 이 두 줄로 접히면서
    상단 바 높이가 통째로 두 배가 된다
  - 좁아지면 덜 급한 것부터 뺀다: 560px 밑에서 몬스터 수, 470px 밑에서 이름과 턴.
    다 넣으려 들면 `다시` 가 화면 밖으로 밀려난다 (500px 에서 실제로 잘렸다)
- [x] 상단 바 아래는 게임영역과 정보영역 둘뿐이다 (`.split`)
  - 게임 1:1 + 정보 7:9 = 16:9. 세로는 정보 9:7 위, 게임 1:1 아래 = 9:16.
    비율이 맞아떨어져서 기준 길이 `unit` 하나로 다 잡힌다.
    `side = min(짧은 변, 긴 변 * 9/16)`, `unit = side/9`
  - `layoutSplit()` 이 px 로 넣는다. CSS 만으로는 "둘을 붙인 상자를 통째로
    최대한 크게" 를 못 짠다. 판 크기도 이미 px 계산이라 같은 자리에 뒀다
  - DOM 은 게임 → 정보 한 순서뿐이다. 가로는 `row`, 세로는 `column-reverse`.
    순서를 뒤집는 대신 방향을 뒤집으면 자리 계산이 한 벌로 끝난다
  - `.split` 에 `overflow:hidden`. 판이 최소 크기(120)에 걸려 넘칠 때 화면이
    스크롤되는 대신 잘리게 둔다
- [x] 정보영역은 카드 여섯 장 (`.info` / `.card`)
  - 가로 2x3(카드 3.5:3), 세로 3x2(카드 3:3.5). 격자는 CSS, 크기는 `--cw`/`--ch`
  - 카드는 칸을 꽉 채우지 않는다. 간격 `g`(≈unit*0.16)와 테두리 여백을 뺀 칸 안에
    비율대로 넣고 가운데 둔다. 칸을 꽉 채우면 간격만큼 비율이 틀어진다
  - 카드 안 글자는 다 `--u` 를 따라간다 (`font-size:clamp(8px, u*.17, 13px)` 의 em 배수).
    px 로 박아 두면 작은 화면에서 카드 밖으로 넘친다
  - 퀘스트·인스펙터·조작 안내가 세 장을 쓰고 셋은 빈 자리(`.card.empty`)다
- [x] 인스펙터 (`#inspect` / `renderInspect`)
  - 탭은 `pointerup` 한 곳에서 가른다. 스와이프 문턱(24px) 에 못 미치면 탭이다.
    따로 `click` 을 달면 스와이프 끝에도 같이 터진다
  - `boardEl.contains(el)` 로 판 위 블럭만 받는다. 드래프트 모달 안에도 같은
    클래스의 블럭이 있어서, `.token` 만 보면 모달을 누른 것까지 딸려 온다
  - `picked` 는 몬스터일 때만 담는다. 플레이어는 `null` 로 두고 `inspectTarget()`
    이 대신 내준다. 죽은 몬스터를 들고 있으면 없는 체력을 적게 되므로,
    목록에 없으면 그 자리에서 놓는다
  - 다시 그리는 때는 값이 바뀌는 자리마다다: `renderHp`(보고 있는 것만),
    `renderExp`/`renderCoin`(플레이어를 볼 때만), `killMonster`, `reset`
  - 값(`b`)은 안 줄이고 이름(`span`)만 줄인다. 좁은 카드에서 숫자가 먼저 잘리면
    카드가 소용이 없다
  - 드랍은 한 줄에 몰지 않고 두 줄로 나눴다. `코인 5 · 경험치 10` 은 좁은
    카드에서 이름을 밀어낸다
- [x] 업그레이드 내역 (`upgradeList`)
  - `DRAFT_CARDS` 를 차례로 훑어 가진 것만 낸다. 고른 순서가 아니라 늘 표 순서라
    자리가 안 흔들린다. 판 위 블럭의 기술 줄과 같은 방식이다
  - 카드를 고른 순간(`takeCard`)에도 다시 그린다. 공격력과 목록이 같이 바뀐다
  - 스텟 줄은 `repeat(auto-fit, minmax(6.5em, 1fr))`. 자리가 되면 두 칸,
    좁아지면 저절로 한 칸으로 돌아온다. px 로 가르면 카드 크기마다 손봐야 한다
  - 스텟과 업그레이드는 `.ins-body` 한 통에 담아 같이 넘긴다.
    따로 굴리면 카드가 좁을 때 둘 다 반쪽만 보인다
  - 퀘스트 목록은 카드보다 길어지면 잘리는 대신 스크롤된다 (막대는 감춘다)
- [x] 쓰러지면 판을 흑백으로 낮춘다 (`.play.over .board`)
- [x] 판은 화면 크기에 맞춰 리사이즈
  - `.board` 는 안 줄어든다 (`flex:none`). 칸을 반올림하다 보면 몇 px 넘칠 때가
    있는데, 줄어들게 두면 가로만 깎여 판이 정사각이 아니게 된다 (547 → 545x547)
  - 판이 340px 밑으로 좁아지면 칸 간격을 2px → 1px 로 줄인다
- [x] 외부 칸은 내부 칸의 1/3 크기로 그린다 (`OUTER_SCALE`)
  - 외부는 적이 어디서 나오는지만 보여 주면 된다. 남는 자리를 내부가 가져간다.
    430px 폭에서 내부 칸이 43px → 52px 로 커졌다
  - 규칙은 그대로다. 좌표도 이동도 스폰도 안 건드렸다. 화면에서 차지하는 자리만 줄였다
  - 칸마다 크기가 달라 더는 `색인 * 간격` 으로 자리를 못 낸다. `computeAxis()` 가
    한 축의 크기·시작 위치를 미리 배열로 만들고, 가로세로가 그것을 각각 참조한다.
    그래서 왼쪽 띠의 안쪽 행 같은 칸은 좁고 길쭉해진다
  - 내부 칸 C 는 `전체 = 6*C + 4*(C/3) + 간격*9` 를 풀어서 낸다
- [x] 토큰은 늘 정사각형. 칸의 짧은 변에 맞춰 가운데 둔다
  - 좁고 길쭉한 칸을 꽉 채우면 고블린이 길쭉한 알약 바닥에 처박힌 꼴이 된다
  - 가운데로 미는 것은 `left`/`top` 으로 한다. `transform` 은 칸의 원점을 그대로
    가리켜야 자리 계산이 한 군데로 모이고, 테스트도 자리를 되읽을 수 있다
- [x] 내부 6*6 둘레에 노란 테두리
  - 갈 수 있는 범위가 바닥 색만으로는 헷갈려서 경계를 선으로 한 번 더 그렸다
  - 테두리 위치·크기는 `MIN`/`MAX` 에서 계산한다. 외부 줄 수를 바꿔도 따라간다
- [x] 사방이 막히면 안내 문구가 `갇혔다. 다시 를 눌러라` 로 바뀐다
  - 규칙에 없는 것을 넣었다. 승패 규칙이 아직 없어서, 갇히면 어떤 입력도 안 먹는데
    그 상태가 고장인지 규칙인지 화면상 구분이 안 된다

# 끝난 판 팝업
- [x] `showEnd('over'|'clear')` 하나로 둘을 다 낸다 (`#endpop`)
  - 다른 것은 제목·문구와 줄 몇 개뿐이다. 팝업을 둘로 나눌 까닭이 없다
  - `.endpop[hidden]` 를 따로 적어야 감춰진다. `display:flex` 가 `[hidden]` 을 이긴다
    (드래프트 모달과 같은 함정)
  - z-index 는 드래프트(100)보다 위(110)다
- [x] `ended` 가 서면 `act()` 가 아무 입력도 안 받는다
  - `over` 와 따로 둔다. 클리어는 쓰러진 것이 아니라서 `over` 가 아니다
- [x] 팝업이 떴으면 드래프트를 안 연다 (`while (!over && !ended && ...)`)
  - 안 막으면 팝업 밑에서 드래프트가 열려 고를 수 없는 채로 페이즈가 멈춘다
- [x] 클리어 판정은 `advanceQuest` 가 마지막 묶음을 넘긴 자리다
  - `startGroup(groupIndex + 1)` 뒤에 `allDone` 이면 클리어. 판정할 자리가
    이미 거기 하나뿐이라 새로 만들 것이 없었다

# 그리기
- [x] 칸은 배경으로 깔고, 플레이어·몬스터는 그 위에 얹은 `.token` 으로 둔다
  - 칸의 내용물을 갈아 끼우는 대신 토큰을 `transform` 으로 옮긴다.
    그래야 이동이 애니메이션이 된다 (`transition:transform .13s`)
- [x] 몬스터 등장 효과는 안쪽 `.glyph` 에 건다
  - 토큰 자신의 `transform` 은 좌표를 잡는 데 이미 쓰고 있다.
    거기에 `scale` 애니메이션을 얹으면 몬스터가 판 왼쪽 위로 튀어 나간다

# 스프라이트
- [x] 규격: **64x64, 알파 채널 있는 PNG**. 후처리 없이 그대로 쓴다
  - `images/` 에 넣고 `KINDS` 의 `img` 에 파일 이름만 적으면 끝이다
  - 한때 384px 에 알파 없는 RGB 를 받아서 검정 배경을 잘라 쓰던 시절이 있었다.
    그 후처리는 이제 없다. 새 그림은 처음부터 알파를 갖고 온다
- [x] 토큰 안에 `<img class="glyph">` 로 넣는다
  - 종류별 파일은 `KINDS` 표에만 적혀 있다 (`player.png`, `goblin.png`, `goblin_rider.png`)
- [x] `image-rendering: pixelated`
  - 원본 64px 이 40~70px 로 그려진다. 1:1 언저리라 픽셀 아트는 pixelated 가 또렷하다
  - 384px 원본이던 때는 반대였다. 10배 축소라 픽셀을 왕창 버려 실루엣이 깨졌고,
    그때는 부드럽게 줄이는 쪽이 나았다. 원본 크기가 바뀌면 이 선택도 같이 바뀐다
- [x] 바닥판은 옅은 방사형 그라데이션 + 1px 테두리
  - 스프라이트가 주인공이라 칸을 꽉 채워 칠하면 그림이 안 보인다.
    플레이어는 노란 테, 몬스터는 붉은 테로 누가 누구인지 알린다
- [x] 스프라이트는 블럭을 꽉 채운다 (`height:100%`)
  - 예전에는 아래쪽을 체력 바 자리로 비워 뒀다 (86% → 72% → 65% 로 내려왔다).
    그림이 주인공인데 자리를 뺏기고 있었다. 이제 바를 그림 위에 반투명으로 얹는다
  - 기물(블로커·지역 블럭)도 같다. 원래도 체력 바가 없어 88% 였는데 100% 로 맞췄다
- [x] 체력·경험치 바는 60% 로 낮춰 그림 위에 얹는다. 숫자는 안 낮춘다
  - `.hp` 에 `opacity` 를 걸면 안 된다. 안에 있는 숫자까지 같이 흐려진다.
    바탕(`background` 의 알파)과 채움(`.hp i` 의 `opacity`) 만 따로 낮춘다
  - 숫자는 읽으라고 있는 것이라 불투명하게 둔다. 검은 테는 그대로라 밝은 그림
    위에서도 읽힌다
