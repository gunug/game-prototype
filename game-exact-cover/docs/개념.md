# 반박 깊이

틀린 수를 틀렸다고 보이는 데 몇 수를 엮어야 하는가.

한 자리에서 후보가 여럿일 때, 옳은 수를 고르려면 틀린 후보를 전부 쳐내야 한다.
그중 가장 깊게 파야 하는 것이 그 자리의 깊이다.

| 깊이 | 뜻 | 사람이 하는 일 |
|---|---|---|
| 0수 | 후보가 애초에 하나 | 고를 게 없다. 그냥 채운다 |
| 1수 | 놓자마자 못 덮는 칸이 생긴다 | 한 수만 봐도 틀림이 보인다 |
| 2수 | 놓고 이어지는 수를 놓아야 막힌다 | 두 수를 엮어야 모순이 보인다 |
| 3수 | 세 수 | |
| 4수 이상 | | 사실상 탐색 |

## 정의

`깊이(p)` = p 를 놓고 이어서 **어떤** k-1수를 두어도 **반드시** 막히는, 가장 작은 k.

미니맥스 깊이다. "그런 조합이 있다" 가 아니라 "모든 이어짐이 실패한다" 여야
반박이 선다. 그래야 논리적으로 옳다.

- 자리 깊이 = 그 자리 틀린 후보들의 깊이 중 **최대값**. 다 쳐내야 고를 수 있으므로
- 퍼즐 깊이 = 풀이 경로에서 나온 자리 깊이의 **최대값**

## 왜 완전한가

가장 앞선 빈 칸은 **반드시** 덮어야 한다. 그러니 그 칸을 덮는 방법들만 갈라 봐도
빠뜨리는 경우가 없다. 그래서 탐색 폭이 작으면서도 반박이 논리적으로 완전하다.

## 기하학적 의미

- **1수 반박** — 조각을 놓으면 조각보다 작은 주머니가 생기거나, 남은 칸 수가
  조각 크기의 배수가 아니게 된다. 눈에 바로 보인다
- **2수 이상** — 크기는 맞는데 모양이 안 맞는다. 도미노의 체스판 색칠 논증 같은 것.
  한 수 더 놓아 봐야 드러난다

큰 조각을 들쭉날쭉한 필드에 놓으면 1수 반박이 흔해진다. 놓는 족족 구멍이 나서
생각할 게 없어진다.

## 다른 지표와의 관계

| 지표 | 재는 것 |
|---|---|
| 칸당 후보 | 후보가 **몇 개**인가 |
| 확인 비용 | 한 자리를 정하려고 몇 개를 따져야 하는가 |
| 추측 비율 | 따져도 안 좁혀지는 자리의 비율 (= 해가 유일하지 않다) |
| **반박 깊이** | 쳐내는 데 **몇 수**가 필요한가 |

앞의 셋은 후보의 **양**을 본다. 깊이는 쳐내는 **비용**을 본다. 확인 비용이 높아도
후보들이 전부 1수에 죽으면 시시하고, 확인 비용이 낮아도 2~3수를 파야 하면 재미있다.
이모티콘 뱃지가 실제 느낌과 어긋났던 이유다.

## 측정

솔버는 후보의 생사 판정(끝까지 갈 수 있는가)에만 쓰고, 깊이 탐색 자체는 순수 조합이다.

```
각 단계 (읽는 순서로 가장 앞선 빈 칸):
  후보가 하나면            -> 0수
  아니면 CP-SAT 로 생사 판정
  틀린 후보마다 깊이를 재고 최대값을 그 자리 깊이로
```

상한이 필요하다. 4 로 두면 절반이 걸려 변별이 안 됐고, 8 로 올리니 5·7·8수가
갈렸다. 상한을 넘긴 것은 `8+수` 로 표시한다 — 실제 값이 아니라 "그보다 깊다" 는 뜻이다.

반박이 **선다**는 걸 보이는 쪽이 비싸고, **안 선다**는 건 살아남는 갈래 하나만
찾으면 되므로 싸다. 그래서 깊은 퍼즐일수록 오히려 빨리 끝난다.

## 생성 쪽 전망

깊이를 정해 놓고 만들 수 있는가.

- **1수만 나오게** — 된다. 놓으면 구멍이 나는 상황을 제약으로 강제하면 된다
- **2수 이상을 보장** — 직접 제약으로는 안 된다. 깊이는 풀이 과정의 성질이라
  CP-SAT 모델에 넣을 수 없다
- **현실적인 방법** — 반복 루프. 필드 생성 → 깊이 측정 → 얕으면 그 구조를 금지하는
  컷을 추가 → 재생성. 보장이 아니라 수렴을 노린다. 무작위로 뽑아 거르는 것보다는
  훨씬 빠르다. 컷이 얕은 구조를 통째로 잘라내므로
