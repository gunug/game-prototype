# 화면구성
- [x] 퍼즐 고르는 페이지와 푸는 페이지를 나눈다
  - 한 파일 안에서 두 화면을 `hidden` 으로 갈아 끼운다. 페이지 이동이 없어 상태가 유지된다
  - 푸는 화면 상단 바에 퍼즐 이름·난이도·칠해야 할 모양·지우기·목록 버튼
- [x] 클리어하면 다음 퍼즐로 넘어가는 버튼이 뜬다
  - 클리어 전에는 배너가 `pointer-events:none` 이라 누를 수 없다
  - 마지막 퍼즐이면 `퍼즐 목록 →` 으로 바뀐다
- [x] 격자형 타일맵
- [x] 격자는 가로 10칸, 세로 10칸이 되도록 1:1 비율의 조작 공간을 구성하고. 디바이스 화면 크기에 맞춰 리사이즈 하도록 한다.
  - 칸 크기는 min(가용 너비, 가용 높이) / 10 을 내림한 정수 px. 판은 남은 영역 중앙 정렬
  - 상단 바를 뺀 나머지가 가용 영역

# 용어
## 필드
- [x] 블럭이 칠해질 수 있는 공간
  - 활성 칸만 칠할 수 있고, 비활성 칸은 포인터를 무시한다
- [x] 필드 가장 외곽라인에 흰색 글로우 라인
  - 칸마다 테두리를 그리면 모서리가 겹쳐서, 필드와 바깥이 맞닿는 변만 모아
    격자 위에 svg path 한 겹으로 얹는다
## 칠
- [x] 색이 없는 필드에서 드래그를 시작하면 하나의 색이 배정되고 드래그 하면 색이 이어짐
- [x] 색이 배정될때 이미 필드에 있는 색이라면 배정되지 않는다.
  - 칠 하나마다 색이 하나씩 필요하므로 팔레트를 100색(칸 수)으로 잡고 황금각으로 색상환을 돈다
- [x] 이미 색이 들어있는 필드에서 드래그를 시작하면 기존의 색이 이어짐
- [x] 이미 색이 들어있는 필드를 클릭하면 색이 지워짐
  - 클릭 = 다른 칸으로 이동 없이 뗀 경우. 드래그 취소(pointercancel/blur)는 지우지 않음
- [x] 이미 색이 들어있는 필드를 3초이상 홀드하면 해당색상의 모든 필드가 지워짐
  - 누르는 동안 지워질 칠 전체가 3초에 걸쳐 밝아진다.
    아무 표시 없이 3초를 기다리게 두지 않으려고 넣었다
  - 칸을 옮기면 드래그로 보고 홀드를 취소한다
  - 홀드로 지운 뒤에는 그대로 드래그를 끝낸다. 안 그러면 지운 색으로 다시 칠하게 된다
## 모양
- [x] 어떤 칠이 연속드로 배치된 형태
  - 같은 색으로 4방향 연결된 덩어리 하나 = 칠 하나
- [x] 각 모양은 0,90,180,270 회전한 형태는 같은 모양으로 본다.
  - 좌우 반전은 다른 모양으로 본다 (스펙에 반사 언급이 없어 회전만 인정)
  - 대칭이면 회전형이 겹쳐서 종류가 줄어든다

    | 회전 형태 | 모양 |
    |---|---|
    | 1종 | O4 (정사각) |
    | 2종 | I3, I4, S4 (막대와 번개) |
    | 4종 | L3, T4, L4, L5, P5, T5, V5, W5, Y5 |

    안 쓰는 것 중엔 X5(십자) 1종, I5 2종, Z4·Z5 2종
  - 회전 종류는 점수에 따로 넣지 않는다. 배치를 셀 때 회전형을 펼쳐 세고 같은 칸
    집합은 중복 제거하므로 **칸당 후보에 이미 들어 있다**. 따로 가중치를 주면 이중 계산이다

    | 모양 | 회전 | 60칸 배치 | 칸당 후보 | 난이도 |
    |---|---|---|---|---|---|
    | O4 | 1 | 38 | 2.5 | 8 |
    | S4 | 2 | 67 | 4.5 | 35 |
    | L4 | 4 | 124 | 8.3 | 51 |

  - 값 자체는 데이터와 화면에 드러낸다. 푸는 화면 모양 옆에 `회전 n`, 칩 툴팁에 칸 수와 함께
- [x] 칠한 모양이 칠해야 할 모양과 일치 하면 각 칸에 빗금 (유리질감) 그라디언트 표시
- [x] 칠한 모양이 칠해야 할 모양과 일치 하지 않으면 유리질감 그라디언트 미표시
  - 드래그를 뗄 때마다 모든 칠을 다시 보고 일치하는 덩어리에만 `.match` 를 붙인다

# 스테이지
- [x] 좌측에 리스트 형태로 스테이지를 출력한다.
  - 49개. 모드별로 나누고 각 구간 안에서 난이도 낮은 순
  - 사이드바가 아니라 **별도 페이지**다. 카드 격자로 깔고, 카드마다 모양 칩·난이도·클리어 표시
  - 카드는 최소 92px 로 작게 잡아 한 화면에 많이 보이게 했다. 카드 이름은 번호만 (모드는 묶음 제목에 있음)
  - 머리말에 `n / 49 클리어` 진행 상황을 보여 준다
- [x] 클리어한 스테이지는 체크표시 한다.
  - LocalStorage(`exact-cover.cleared`)에 저장해 다시 열어도 유지
- [x] 각 스테이지에 1~100 난이도를 표시한다.
  - 값이 클수록 배지가 브랜드색에 가까워진다
- [x] 푸는 방식 뱃지를 표시한다 — 😒 그냥 / 😐 중간 / 😎 추론 / 🤮 탐색
  - 카드와 푸는 화면 상단 바 양쪽에. 이미 재 둔 값으로 나누므로 다시 풀지 않는다
  - 화면에는 이모티콘만 띄우고, 이름은 툴팁과 `data-band` 로 남긴다

    | 뱃지 | 이름 | 조건 | 뜻 | 개수 |
    |---|---|---|---|---|
    | 🤮 | 탐색 | 추측 20% 이상 | 따져도 안 좁혀져 시행착오가 필요하다 | 6 |
    | 😎 | 추론 | 확인비용 2.0 이상이고 추측 0% | 후보가 여럿인데 따져 보면 하나로 좁혀진다 | 4 |
    | 😒 | 그냥 | 확인비용 1.5 미만 | 후보가 늘 하나뿐이라 따질 것 없이 채워진다 | 22 |
    | 😐 | 중간 | 나머지 | 그 사이 | 17 |

    위에서부터 먼저 맞는 것을 쓴다. 수도쿠 같은 맛은 **😎 추론** 구간인데 49개 중 4개뿐이다.
    제약이 "정확히 덮는다" 하나뿐이라 자명하거나 안 보이거나 둘 중 하나로 쏠린다
- [x] 클리어한 퍼즐은 반투명하게 보여 준다
  - 숨기거나 잠그지 않는다. 자리도 그대로다. 다시 눌러 풀 수 있고, 올려 두면 또렷해진다
  - 클리어 배너가 `class="done"` 이었는데 전역 `.done{position:absolute}` 규칙이라
    클리어한 카드가 배너 자리로 튀어 나갔다. 배너 클래스를 `clear-banner` 로 분리

## 모드
- [x] single — 조각 한 종으로 덮는다. 39개
- [x] dual — 조각 두 종을 섞어 덮는다. 10개
  - 목록에 `조각 한 종` / `조각 두 종` 머리말로 구분해 보여 준다
  - 두 종이면 어느 쪽 모양이어도 맞는 것으로 본다
  - 조각 크기가 다르면 조각 수로 칸 수가 정해지지 않으므로, 생성 모델은
    조각 수 대신 **칸 수**를 고정한다
  - 모양마다 최소 2조각 이상 쓰도록 걸어 한쪽만으로 덮는 답을 막는다
  - 두 종 구성

    | 모양 | 칸 | 배치 | 칸당 후보 | 해 | 난이도 |
    |---|---|---|---|---|---|---|
    | I3 + L3 | 48 | 162 | 10.1 | 4004 | 48 |
    | I3 + S4 | 60 | 137 | 7.9 | 1 | 50 |
    | O4 + V5 | 76 | 187 | 11.7 | 16 | 54 |
    | S4 + P5 | 72 | 200 | 12.9 | 2 | 55 |
    | I4 + W5 | 80 | 250 | 14.5 | 1 | 56 |
    | L3 + T4 | 60 | 261 | 14.9 | 5000+ | 63 |
    | T4 + S4 | 72 | 253 | 14.1 | 26 | 63 |
    | L4 + T5 | 76 | 279 | 16.3 | 1 | 64 |
    | L3 + L4 | 66 | 302 | 15.7 | 5000+ | 65 |
    | T4 + L5 | 72 | 241 | 14.8 | 1 | 67 |

    앞 5개는 작은 조각 위주(3~4칸), 뒤 5개는 4칸 + 5칸 조합이다
    4+5 조합이 크기를 섞는 만큼 어려워지진 않았다. 작은 조각을 섞는 쪽이 후보가 더 늘어난다

## 문제
- [x] 칠해야할 모양을 보여준다
  - 상단 바에 미니 격자로 표시. 두 종이면 나란히 둘. 고르는 페이지 카드에도 같이 보여 준다
- [x] 칠해야할 모양으로 채울 수 있는 필드를 생성 (칠할 필요 없는 필드는 비활성화)
  - `tools/generate.py` 가 OR-Tools CP-SAT 로 미리 풀어 만들고, 게임은 구운 결과만 읽는다.
    런타임 생성기(`buildField`, `mulberry32`)는 삭제
  - 모델: 칸마다 `그 칸을 덮는 조각 수 == 활성 여부`, 칸 수 고정.
    이 제약이 정확한 덮개를 보장하므로 만들어진 필드는 항상 풀린다
  - 조밀도(frac)로 필드 생김새를 조절한다. 1.0 이면 항상 직사각형이 나와서
    0.55~0.85 대를 쓰고, 그 안에서 무작위 가중치로 골라 문제마다 다르게 만든다
  - 이전 성장식 생성기는 뚱뚱한 필드를 만들지 못했다 (42칸 요청에 18칸에서 멈춤)
  - `python tools/generate.py` 는 single, `--dual` 은 dual 을 뽑는다
  - `python tools/generate.py --verify` 로 구운 필드를 다시 풀어 확인. 49개 모두 통과

## 검사
- [x] `node tools/smoke.mjs` — DOM 을 흉내내고 index.html 스크립트를 끝까지 실행한다
  - 고르는 페이지: 모드별 묶음, 카드 개수, 진행 표시, 난이도 구간별 오름차순, 카드 모양 칩,
    방식 뱃지 네 종류, 클리어 표시가 붙되 다시 누를 수 있는지
  - 조상 없는 `.foo{position:absolute}` 같은 전역 규칙이 카드가 쓰는 클래스와 겹치는지
    CSS 를 훑어 확인한다. 위 배너 사고를 잡는 검사
  - 화면 전환: 카드를 누르면 푸는 화면, 뒤로 누르면 목록, 다음 버튼이 다음 퍼즐을 연다
  - 푸는 페이지: 격자 100칸, 활성 칸, 모양 미리보기, 필드 외곽선 path,
    클릭 시 칠해짐, 목표 모양을 칠하면 유리 질감이 붙음
  - 홀드: 누르는 동안 표시, 홀드하면 같은 색 전부 삭제, 옮기면 취소,
    짧게 누르면 한 칸만 삭제. 타이머를 직접 돌려 3초를 기다리지 않는다
  - 두 종 스테이지를 열면 모양 칩이 둘 나오는지
  - 문법 검사(`new Function(js)`)만으로는 정의가 사라진 걸 못 잡는다.
    `measure.py --apply` 가 스테이지 블록을 갈아치우면서 `readField` 를 지웠고,
    파싱은 통과해 그대로 배포돼 화면이 비어 나갔다
  - `emit_stages` 가 `readField` 까지 같이 내보내도록 고쳤고, 스모크 테스트로 막았다

## 난이도
- [x] 측정해서 1~100 으로 매기고 쉬운 순으로 정렬한다
  - `python tools/measure.py --apply` 가 재고 index.html 의 STAGES 를 다시 쓴다
  - `tools/stages.json` + `tools/stages-dual.json` 을 읽고 결과를 `tools/measured.json` 에 쓴다
  - 모델이 작아 솔버를 병렬로 돌리면 손해라, 워커는 1개로 두고 스테이지 단위로
    프로세스를 나눈다
  - 솔버가 뱉는 `num_conflicts`/`num_branches` 는 안 쓴다. CP-SAT 전처리가 정확한 덮개에
    너무 강해서 전부 0 으로 끝나 변별이 안 된다
  - 쓰는 값

    | 지표 | 재는 법 | 가중치 |
    |---|---|---|
    | 칸당 후보 | 칸 하나를 덮을 수 있는 배치가 평균 몇 개인가. 솔버 없이 센다 | 0.20 |
    | 확인 비용 | 한 자리를 정하려고 후보를 몇 개나 따져 봐야 하는가 | 0.15 |
    | 이어칠 성공률 | 왼쪽 위부터 이어 칠하는 사람 흉내 30회 중 완주 비율 | 0.22 |
    | 헛칠 | 이미 글러버린 시점(솔버 판정)과 실제로 막히는 시점의 간격 | 0.18 |
    | 추측 비율 | 후보를 다 따져도 둘 이상 살아남는 자리의 비율 | 0.10 |
    | 얽힘 | `SufficientAssumptionsForInfeasibility()` 최소 모순 집합 크기 | 0.08 |
    | 분량 | 조각 크기와 칸 수 | 0.07 |

  - 앞의 두 개는 나중에 넣었다. 두 종이 실제로 훨씬 어려운데 점수가 안 따라왔고,
    원인이 **같은 넓이에 놓는 방법의 수**였다

    | | 칸당 후보 | 배치 중앙값 |
    |---|---|---|
    | single | 5.6 | 61 |
    | dual | 13.3 | 245 |

    같은 60칸에서 single `S4` 는 배치 67개, dual `L3+T4` 는 261개다
  - 강제 비율은 솔버가 증명한 전역 성질이라 사람이 알아볼 수 있는지를 담지 못한다.
    같은 강제 100% 라도 후보 1개짜리는 눈에 바로 보이고 8개짜리는 다 따져 봐야 한다.
    그래서 강제 비율은 점수에서 빼고, 확인 비용과 추측 비율로 대체했다
  - 해의 개수와 최소 교체 크기도 재지만 점수에는 안 넣고 참고만 한다
  - 처음엔 완전 무작위로 놓는 방식이었는데 모든 문제가 성공률 0% 라 변별이 안 됐다.
    사람은 빈 칸을 아무 데나 남기지 않으므로 가장 앞선 빈 칸부터 채우게 바꿨다
  - 측정 결과

    | 모드 | 개수 | 점수 범위 | 중앙값 |
    |---|---|---|---|---|
    | single | 39 | 6 ~ 53 | 39 |
    | dual | 10 | 48 ~ 67 | 59 |

    점수는 절대 기준이라 100 까지 여유가 있다

- [x] single 이 전반적으로 너무 쉽다 — dual 로 답했고, 점수도 그에 맞게 다시 짰다
  - 39개 중 30개가 강제 100%, 30개가 해 1개. 구석부터 유일한 자리를 채우면 끝이라
    생각할 여지가 없다. 되돌리기가 공짜라 틀려도 손해가 없는 것도 겹친다
  - 조각이 클수록 오히려 쉽다. 경계에 갇혀 놓을 자리가 굳기 때문

    | 조각 크기 | 평균 강제 | 해 중앙값 |
    |---|---|---|
    | 3칸 | 50% | 14 |
    | 4칸 | 93% | 1 |
    | 5칸 | 98% | 1 |

    커브를 "펜토미노가 어렵다"고 깔았는데 데이터는 반대였다
  - 손볼 방향: 조각은 작게 필드는 크게, 강제 70% 넘는 문제는 폐기,
    필드에 구멍이나 폭 1~2칸 통로 넣기
  - dual 이 여기에 대한 첫 답이다. 전역 제약이 하나 늘어 국소 추론만으로 안 풀린다
